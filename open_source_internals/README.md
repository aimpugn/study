# 오픈소스 내부 깊이 배우기

## 개요

이 폴더는 오픈소스 소프트웨어의 내부 로직, 코드, 알고리즘을 실제 소스와 실제 실행으로 깊게 배우는 곳입니다. 데이터베이스, 운영 체제, 런타임, 메시지 시스템처럼 분야는 달라도 배우는 방법은 같습니다.

1. 공개된 소스를 Docker 이미지 안에서 디버그 정보와 함께 빌드합니다. 학습자는 실행되는 바이너리와 정확히 같은 소스를 읽습니다.
2. 쿼리나 명령 하나를 실행하는 동안 디버거와 추적기로 실제로 지나간 함수, 소스 줄, 값, 시스템 콜을 기록합니다.
3. 설명은 그 기록과 소스, 공식 문서에서만 가져오고, 근거가 없는 설명에는 추론이라고 표시합니다.
4. 학습자는 결과를 보기 전에 먼저 예측하고, 직접 실행해 확인합니다.

최종 목표 화면은 브라우저입니다. 왼쪽에서 쿼리나 명령을 실행하면 그 요청을 처리하는 소스 줄로 오른쪽 화면이 옮겨 가고, 왼쪽 시각화가 그 순간 어떤 일이 일어나는지 보여 줍니다. 별도 프로그램을 설치하지 않아도 누구나 브라우저로 내용을 볼 수 있게 하는 것이 목표입니다.

지금은 [작업대](workbench/README.md)가 이 화면의 첫 형태입니다. 브라우저에서 SQL을 실행하면 PostgreSQL 백엔드가 gdb 중단점에 멈춘 단계들이 왼쪽에 나오고, 고른 단계의 소스 줄과 그 순간의 값, 호출 스택이 오른쪽에 나옵니다. 저장한 기록을 HTML 파일 하나로 만든 재생본은 서버 없이 열립니다. 왼쪽의 시각화는 아직 단계가 지나는 소스 디렉터리 층의 경로 그림 하나이고, 주제마다 다른 시각화(버퍼, 페이지 등)는 없습니다.

## 분야와 주제

| 분야 | 주제 | 다루는 질문 | 상태 |
| --- | --- | --- | --- |
| `database/` | [PostgreSQL 18.6](database/postgresql/README.md) | SELECT 한 줄이 지나는 경로, 행 버전과 스냅숏, `synchronous_commit`이 바꾸는 것 | 실습 문서와 작업대 완료, 사용자 실습 대기 |

주제와 상관없이 함께 쓰는 도구는 [`workbench/`](workbench/README.md)에 있습니다.

분야 폴더는 첫 주제가 생길 때 만듭니다. 앞으로 생길 수 있는 분야는 `os/`(Linux 커널), `runtime/`(Node.js, JVM), `messaging/`(Kafka), `framework/`(Spring), `language/`(컴파일러와 언어 런타임) 같은 것입니다.

## 새 주제를 더할 때

주제 하나는 `<분야>/<오픈소스 이름>/` 폴더 하나입니다. [PostgreSQL 실습](database/postgresql/README.md)이 현재 기준 예입니다. 폴더에는 아래 네 가지를 두고, 작업대로 보려면 다섯째와 여섯째를 더합니다.

- `Dockerfile`: 공식 배포처의 소스를 체크섬으로 확인하고, 최적화를 끈 디버그 빌드로 만듭니다. 소스 트리는 이미지 안에 남깁니다.
- `README.md`: 질문, 실제 기록, 단계별 설명, 흔한 오해, 먼저 예측하고 실행하는 실습 순서로 씁니다.
- `scripts/`: 실습을 재현하는 명령입니다. 저장소 루트에서 실행할 수 있게 만듭니다.
- `evidence/`: 설명과 정답이 기대는 실제 실행 기록입니다. README가 처음 인용하는 자리에서 각 파일로 링크합니다.
- `workbench.json`: 작업대가 읽는 주제 정의입니다. 컨테이너와 이미지 이름, 추적 스크립트, 감시 목록과 예시, 디렉터리별 분류 이름을 적습니다. 추적 스크립트의 출력은 PostgreSQL의 `scripts/trace.py`와 같은 기록 형식이어야 합니다.
- `replays/`: `workbench export`로 만든 재생본입니다. 각 재생본은 `evidence/`의 기록 하나에서 만듭니다.

같은 주제의 개념 문서가 저장소의 다른 축에 있으면 서로 링크합니다. 예를 들어 PostgreSQL의 개념 정리는 [`database/deep-dive/postgresql/`](../database/deep-dive/postgresql/18-postgresql-deep-dive.md)에 있습니다. 개념 축은 원리를 설명하고, 이 폴더는 특정 오픈소스의 실제 소스와 실행을 근거로 삼습니다.
