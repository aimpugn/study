## 4. 질문별로 알게 된 것
**질문 1**
- REQUIRES_NEW는 연결이 두 개 필요합니다. 바깥 C1 "떼어 둠"과 안쪽 C2 "빌림"이 같은 +454 ms에 찍혀 있습니다. [화면에서 확인: 주요 순간 줄]
- 떼어 둔 연결은 스레드에서만 떨어지고, 서버에서는 트랜잭션이 열린 채 남습니다. [화면에서 확인: 용어 설명 "떼어 둔 연결", 같은 행 장면의 C1 "idle in transaction, xid 753"]
- BEGIN은 setAutoCommit(false) 호출 때가 아니라 첫 UPDATE와 같은 묶음으로 나갔습니다. REQUIRED 장면에서 +8.20은 "보낸 것 0개", +9.35에 "BEGIN + … UPDATE"가 있습니다. [화면에서 확인: 트레이스 두 줄]
- 요약 줄은 REQUIRED에서도 "풀이 연 연결 C1, C2"라고 하지만 트레이스에는 C1만 빌렸습니다. C2가 언제 열렸는지는 화면에서 알 수 없었습니다. [화면에서 알 수 없었다]

**질문 2**
- 풀이 1칸이면 안쪽이 연결을 못 얻고 2,003 ms 잠든 뒤 SQLTransientConnectionException이 납니다. 바깥은 CannotCreateTransactionException을 받고 ROLLBACK됩니다. [화면에서 확인: +2,592 주요 순간, 요약 줄]
- 풀에 칸이 있어도 같은 행이면 C2가 753을 기다리고, 3 s 뒤 55P03으로 끊깁니다. [화면에서 확인: 같은 행 장면의 "끊은 것" 줄]
- 서버 교착 검사는 NoDeadlock이라고 기록됩니다. 앱 스레드의 기다림이 고리에 들어가 서버가 보지 못한다는 해석은 화면이 [추론]으로 표시했습니다. [화면에서 확인: NoDeadlock 함수 기록] [추측: 해석 부분]
- 2,003 ms의 설정값은 화면에서 알 수 없었습니다. 설정 칸에는 "최대 1칸 실험 설정"만 있습니다. [화면에서 알 수 없었다]

**질문 3**
- REQUIRED에서 안쪽이 실패하고 바깥이 삼키면 전체가 롤백되고, 바깥은 UnexpectedRollbackException을 받습니다. kim·lee 모두 100·200 그대로입니다. [화면에서 확인: 요약 줄, 용어 설명 "롤백 전용 표시"]
- NESTED는 저장점 이후 변경만 되돌립니다. kim 100→90은 남고 lee는 200 그대로입니다. [화면에서 확인: 요약 줄, 용어 설명 "ROLLBACK TO SAVEPOINT"]
- REQUIRES_NEW에서 안쪽이 커밋된 뒤 바깥이 실패하면 안쪽이 남는지는 화면에서 알 수 없었습니다. 이 장면은 바깥이 성공하는 경우뿐입니다. [화면에서 알 수 없었다] 제 추측은 남을 것 같습니다. [추측]
