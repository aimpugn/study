## 2. 첫인상(60초)과 첫 세 번의 조작

처음에는 복잡한 관측 도구처럼 보였습니다. 상단에 전파 옵션과 실행 버튼이 있고, 가운데에는 Spring·HikariCP·PostgreSQL 상태, 아래에는 시간표와 호출 사슬이 있었습니다. 전파 옵션을 고르면 나머지 화면이 바뀌는지부터 확인하려 했습니다.

| 순서 | 한 일 | 기대 | 이해 | 헷갈림 |
|---|---|---|---|---|
| 1 | `REQUIRES_NEW` 선택 | 옵션별 결과 비교 | 결과 요약에 C1·C2 각각 COMMIT, 잔액 변화가 표시됨 | C1·C2가 정확히 무엇을 가리키는지 처음엔 몰랐음 |
| 2 | `REQUIRES_NEW · 같은 행` 선택 | 같은 행을 건드리면 달라지는지 확인 | C2가 transactionid 753을 기다리다 timeout, 두 트랜잭션 모두 ROLLBACK으로 표시됨 | 앱 쪽 대기와 DB 락 대기의 연결을 한눈에 이해하기 어려웠음 |
| 3 | `NESTED · 안쪽 실패` 선택 | 안쪽 실패가 바깥에 미치는 영향 확인 | SAVEPOINT 생성, `ROLLBACK TO SAVEPOINT` 후 C1 COMMIT으로 요약됨 | 하위 트랜잭션 표기가 독립 커넥션을 뜻하는지는 이 화면만으로 단정하기 어려웠음 |

## 4. 다 써 본 뒤 이 화면이 보여 주는 것

[화면에서 확인] 이 화면은 상단의 전파 시나리오를 선택하고 실행 결과를 코드, Spring 호출, HikariCP 연결, PostgreSQL 트랜잭션, 시간표로 따라가 보는 관측 화면이라고 이해했습니다.  
[화면에서 확인] 시나리오 설명과 결과 요약은 위쪽에, 호출별 시간과 연결 흐름은 아래 타임라인에, 선택한 호출의 설명과 사슬은 오른쪽에 나뉘어 있었습니다.  
[추측] 각 시나리오는 특정 환경을 보여 주는 실험 장면으로 보이며, 화면의 숫자를 모든 Spring·DB 환경에 그대로 적용할 수 있는지는 알 수 없었습니다.

## 5. 질문별로 배운 것

**1번 질문 — 글인가, 실습인가?**

[화면에서 확인] 상단 `REQUIRED`, `REQUIRES_NEW`, `NESTED` 버튼을 누르자 설명·코드·결과 요약이 바뀌어, 설명과 실행 관측을 결합한 화면이라고 알았습니다.

**2번 질문 — 옵션 결과를 비교할 수 있나?**

[화면에서 확인] `REQUIRES_NEW` 요약에서는 C1과 C2가 각각 COMMIT했고, `NESTED` 요약에서는 SAVEPOINT로 되돌린 뒤 C1이 COMMIT했습니다.  
[화면에서 확인] REQUIRED 안쪽 실패 장면에서는 C1이 ROLLBACK하고 잔액도 유지됐으며, 화면은 바깥 호출에서 `UnexpectedRollbackException`이 발생했다고 표시했습니다.  
[화면에서 확인] 상단 실행 a/b와 일부 장면의 c/d 버튼으로 다시 실행할 수 있었고, `효과`, `갈림`, `시간`, `전부` 필터로 타임라인 표시량을 바꿀 수 있었습니다.

**3번 질문 — 풀과 락 대기도 볼 수 있나?**

[화면에서 확인] `REQUIRES_NEW · 풀 1칸` 설명에는 C1을 보유한 상태에서 풀의 빈 칸을 기다리고 2,000ms 뒤 연결 생성 예외가 났다고 나왔습니다.  
[화면에서 확인] `같은 행` 장면의 하단에는 C2가 transactionid 753의 ShareLock을 기다리다 3초 lock timeout으로 끝났다고 표시됐습니다.  
[화면에서 확인] 아래 용어 풀이에는 스레드에 묶인 연결, `REQUIRES_NEW`의 연결 일시 보류, HikariCP의 빌림·반환 설명이 있었습니다.  
[화면에서 확인] `0.5초 안에 다시 빌림` 장면의 칩과 요약에는 한 C1 연결에서 서로 다른 xid가 차례로 COMMIT한 것으로 보였습니다.  
[추측] 이 장면은 연결 반환 후 재대여 과정을 보여 주려는 듯했지만, 커넥션 풀 설정을 직접 변경해 비교하지는 않았습니다.

## 6. 막히거나 헷갈린 점

처음에는 화면이 조밀해서 어디부터 읽을지 몰랐고, 아래로 내려가야 용어 풀이와 타임라인 안내가 있다는 점도 늦게 발견했습니다. 연결 C1과 DB 트랜잭션 xid가 다른 층위라는 점은 여러 칸을 비교하고 나서야 구분할 수 있었습니다. 숫자는 장면별 측정값으로 읽었고, 일반적인 성능 기준으로 받아들이지는 않았습니다.

## 7. 이 화면에 바라는 것

첫 화면에 “위에서 장면 선택 → 요약 확인 → 시간표 줄 선택 → 오른쪽 설명 읽기” 같은 짧은 시작 안내가 있으면 좋겠습니다. C1/C2와 xid, 앱의 기다림과 DB 락 대기를 연결하는 작은 범례도 초반에 보이면 흐름을 더 빨리 잡을 것 같습니다. 풀 크기나 timeout을 직접 바꿔 보는 조작이 있다면 결과 차이를 더 명확히 배울 수 있겠습니다.
