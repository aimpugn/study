## C1~C5

**C1. [화면에서 확인]** 안쪽 UPDATE는 **C2**로 갔습니다. `REQUIRES_NEW · 같은 행`의 위쪽 구성도에서 C2가 `UPDATE acct SET balance = balance + 10...` 요청을 보내고, 바깥 연결 **C1**은 `753` 트랜잭션으로 남아 있었습니다. 오른쪽 `막힌 동안 찍은 관찰`(+2,653~+3,102ms)에는 C1이 `idle in transaction / Client/ClientRead`, C2가 `active / Lock/transactionid`라고 나옵니다. **C1은 서버 쪽 트랜잭션은 열린 채, Spring 스레드에서는 잠시 떼어져 있었습니다.**

**C2. [화면에서 확인]** 같은 행 장면의 `Inner.java` 37행은 안쪽 트랜잭션에만 `SET LOCAL lock_timeout = '3s'`를 설정하고, 39행에서 해당 UPDATE를 보냅니다. DB가 **C1의 xid 753이 끝나기를 기다리게 해** 안쪽 UPDATE가 진행되지 않았고, 결과 칩은 양쪽 ROLLBACK과 `UncategorizedSQLException`을 표시합니다. 시간선에는 `교착 검사 → NoDeadlock`도 보입니다. **[추측]** 관찰상 C2는 xid 753을 기다리지만 C1은 서버에서 `ClientRead` 상태라 DB 락을 기다리지 않습니다. 앱 쪽 바깥 호출이 안쪽의 반환을 기다리는 순환은 있어도 DB의 락 대기 고리는 아니어서, DB는 교착으로 보지 않은 것으로 이해했습니다.

**C3. [화면에서 확인]** `REQUIRES_NEW · 풀 1칸`에서는 C1 하나가 바깥 트랜잭션에 묶여 있어 안쪽이 새 연결을 받지 못합니다. `ConcurrentBag.borrow` 상세에는 약 **2,003ms** 기다린 뒤 시간 초과, 설정에는 `connectionTimeout 2,000 ms`, 결과 칩에는 `CannotCreateTransactionException`이 나옵니다. **[화면에서 확인]** 그동안 안쪽의 DB 요청은 보이지 않습니다. 구성도에는 C1만 있고, 아래 호출 줄은 Spring의 새 트랜잭션 시작에서 Hikari 연결 빌리기로 이어집니다. 앞서 C1이 보낸 작업 뒤 DB는 `idle in transaction`으로 나타나며, 시간 초과 뒤 C1의 ROLLBACK이 보입니다.

**C4. [화면에서 확인]** `REQUIRED · 안쪽이 실패`에서 안쪽은 C1을 함께 쓰다가 예외를 냅니다. 아래 시간순 호출 줄에 `DataSourceTransactionManager.doSetRollbackOnly`가 있고, Outer 코드 31~34행은 예외를 잡습니다. 하지만 참여 중인 트랜잭션에 롤백 전용 표시가 남아 바깥 종료 때 커밋 대신 롤백되고, 위쪽 결과 칩에 `UnexpectedRollbackException`이 표시됩니다. 도움말의 “롤백 전용 표시”도 이 흐름을 설명합니다.

**C5. [화면에서 확인]** 매번 검사하지는 않습니다. `0.5초 안에 다시 빌림`의 `ConcurrentBag.borrow` 상세는 C1이 쉰 시간 **5.7ms**, 검사 창 **500ms**라 “검사 건너뜀”이라고 표시합니다. 오른쪽 HikariPool 코드 168행과 `aliveBypassWindowMs` 값 500도 확인했습니다. 도움말의 추론 표시는 쉰 시간이 이 창보다 길 때 검사한다고 설명합니다.

## M1~M5

**M1. [화면에서 확인]** 호출 줄 맨 앞 숫자는 호출 깊이입니다. 도움말은 바깥 뿌리를 0으로 하고, 추적된 호출과 스택에만 보인 호출을 한 단계씩 센다고 설명합니다.

**M2. [화면에서 확인]** 줄 끝의 `⑂`는 갈림 표시입니다. 도움말의 “보이는 이유”에서 함께 견준 기록들 사이에 그 메서드가 자식을 부른 차례가 둘 이상인 자리라고 설명합니다.

**M3. [화면에서 확인]** 점선 막대와 기울인 글씨는 스택에만 보인 호출입니다. 도움말은 끝 시각이 기록되지 않은 호출이며, 예외가 지나간 흔적이 다른 기록의 스택에 남은 것이라고 설명합니다.

**M4. [화면에서 확인]** `＋2`, `＋5` 같은 표시는 접힌 자식 호출 수입니다. 도움말은 누르면 펼쳐진다고 안내합니다.

**M5. [화면에서 확인]** `◉`는 관찰, `≈`는 추론 표지입니다. 도움말의 출처 표지에는 관찰이 PostgreSQL 상태 뷰에서 읽은 값, JFR이 JVM 메서드 호출 기록, 함수 기록이 PostgreSQL 백엔드 기록, 추론이 다른 기록으로 해석기가 셈한 값이라고 적혀 있습니다. `추론` 표지에 마우스를 올려 봤지만 별도 설명은 확인하지 못해, 계산 방법까지 읽었다고 하지는 않겠습니다.
