- 문제: 세 갈래입니다.

  - (c) 장면 규칙의 Via 연결 근거도 칸의 성격에 들어가지 않습니다.

  - `journey/kernel_insert` 칸 14 「디스크까지 동기화」는 성격이 `observed`이고 dur_ns가 51,871,000입니다.
  - 그런데 이 칸의 이동(사건 64)은 t0 = t1인 instant입니다. 51.9 ms는 사건 65 `syscall`의 dur_ns이고, 이 사건은 `pair` 근거(inferred)로만 붙어 있습니다.
  - 그래서 단계별 안내, 후보 카드 「디스크까지 동기화 51.9 ms」, 함수 줌 머리 「… 51.9 ms · 그중 잠듦 51.3 ms」(screen-function.png)에 ≈ 표지가 없습니다.

  - tx 칸은 `tx` 근거(도출)의 contains로만 경로에 드는데도 `observed`로 보입니다.
  - 주제 시험은 DurNS = 51871.0만 고정하고 성격은 보지 않아서, 지금 꼴을 그대로 굳힙니다.
- 제안: 마디마다 경로 성격을 누적합니다(부모 쪽 경로 성격과 들어온 연결의 성격 가운데 약한 것). 칸의 머문 시간이 나무에서 오면 그 마디의 경로 성격을 길이의 성격(예: `dur_nature`)으로 따로 싣고, 화면은 길이 옆에 그 표지를 붙입니다. 지금처럼 마디가 국소 성격만 갖는 것이 의도라면, 규칙 6의 글을 고치고 까닭을 적어야 합니다.
- 재현: view.json에서 `routes[id=journey/kernel_insert#0].steps[14]`의 `nature`와 `dur_ns`를 보고, run JSON의 사건 64·65와 연결 10을 맞대 봅니다.
