## 요청(요지)

재검토라 앞선 지적 1~14의 처분이 맞게 됐는지와 그 고침이 만든 회귀만 보라고 했습니다. 받지 않거나 일부만 받은 지적(10의 시험 방법, 11의 도출, 12의 미기록)의 까닭이 타당한지, 특히 10의 "방향 시험이 차이가 0 둘레인 12벌에서 변이를 못 잡았다"는 주장이 맞는지 보라고 했습니다. 회귀로는 `PROV_FIXES`와 로더가 다른 입력의 판정을 바꾸는지, 검사 3의 값 걷기가 동적 열쇠·빈 목록·스칼라 목록·run attrs에서 틀리는지, `LinkIndex`의 id 정렬이 원본과 다른 차례를 만들 수 있는지, txlab 읽기 구간의 변경이 내보내기·변이·재추출을 깨는지, 다시 세게 한 칸이 규칙과 다른 원본을 받아 주는지, `Export`의 recover가 숨기면 안 되는 것을 숨기는지, 문서가 코드와 맞는지를 들었습니다. 답은 판정 한 줄, 지적마다 닫힘·일부 닫힘·열림, 새 문제(번호, 심각도, 위치, 무엇, 근거, 제안), 확인한 것과 못 한 것.

## 3. 새 문제

**N1. 낮음 — 검사 3이 Go 타입이 정해진 그릇을 걷지 않음**
- 위치: `internal/atlas/checks.go:71-86`. type switch가 `map[string]any`와 `[]any`만 걷습니다.
- 근거(overlay 시험 `zz_walk_test.go`):
  - `f: map[string]string{"conn":"C2"}`는 오류 0개입니다. 같은 내용을 `map[string]any`로 넣으면 실패합니다.
  - `params.user: []map[string]any{{seq:1}}`도 오류 0개입니다.
  - 지금 네 적재기의 attrs에는 이런 값이 0개입니다(reflect로 훑음).
- 제안: 걷지 못하는 그릇 종류(Map, Slice, Array, Struct, Ptr)를 만나면 오류로 봅니다. 또는 JSON으로 썼다 읽은 run에 검사합니다.

**N2. 낮음 — 손으로 고친 대응표의 출처를 로더가 그대로 받음**
- 위치: `topics/pgsql/roles/roles.go:69`의 `r.Prov = f[3]`.
- 무엇: 표를 다시 만드는 `cmp`는 손으로 돌리는 명령이고 `go test`에 들어 있지 않습니다. 고치기 전에는 검사 4의 기대가 표시 파일을 고쳐야만 바뀌었습니다. 이제는 생성기를 거치지 않고 표의 출처 칸만 바꿔도 바뀝니다.
- 근거: scratchpad 사본에서 tx의 `$.steps[]` 출처를 관찰에서 도출로 바꾸니 `Load`가 오류 없이 "도출"을 돌려줬습니다(`zz_roles_test.go`).
- 제안: 표의 출처가 표시 파일과 다르면 규칙 칸에 `출처 고침(표시 X → Y)`가 있어야 받게 합니다. `roles.py`도 `PROV_FIXES`의 열쇠가 모두 실제 행에 쓰였는지 확인하면 좋습니다.

**N3. 낮음 — `checkJoin`이 Z 수를 메시지와 견주지 않음**
- 위치: `topics/pgsql/spring/spring.go`의 `checkJoin`(약 1100~1118행).
- 무엇: 두 수가 같은지만 봅니다. `join[1]`(Z 수)은 메시지에서 다시 셀 수 있습니다.
- 근거: 5-nested/a는 원래 `join [12 12]`, 요청 12개, Z 메시지 12개입니다. `join`을 `[3,3]`으로 바꿔도 적재가 통과합니다(`zz_join_test.go`).
- 제안: `join[1] == len(requests)`(Z 수)도 확인합니다. `join`의 역할은 '출처'라 저장하는 것 자체는 괜찮습니다.

**N4. 낮음(문서) — `reads.py`가 보이는 것보다 넓게 인용함**
- 위치: `roles.py`의 `_READS`(대응표 규칙 칸)와 메모 7.
- 무엇: 두 곳 모두 "그 밖은 모두 다음 질의를 받은 때"를 `reads.py`의 결과처럼 적습니다. 실제로 `reads.py`는 "다음 관찰 시작과 같지 않고, 그보다 늦지 않음"만 셉니다. "다음 질의"는 해석기 규칙에서 나온 결론이고, 기록에는 그 시각이 없습니다.
- 제안: 셈과 규칙에서 나온 결론을 나눠 씁니다.
