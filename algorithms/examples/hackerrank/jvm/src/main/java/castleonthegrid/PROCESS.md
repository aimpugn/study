## 30초 카드

- **문제 신호**: 격자에서 시작→목표 최단 **이동 횟수**. 한 이동은 룩처럼 한 방향으로 미끄러지며 그 직선 위 아무 칸에나 선다.
- **한 줄**: BFS로 각 칸의 최단 거리를 dist에 파동처럼 채우고, 목표를 큐에서 꺼내는 순간의 값이 답이다.
- **키워드**: BFS, dist[][], 파동(레벨), 미끄러짐 이웃 = `for(방향) → while(nx += d)`.
- **함정 단서**: 경로를 모으지 마라(그건 지수 DFS다). 최단은 "경로 중 최소"가 아니라 "dist 채우기". visited(=dist) 없으면 무한 루프.

## 어디서 막혔나 (재발 방지용 실제 실수 기록)

첫 시도에서 "목표까지 갈 수 있는 경로를 전부 모아 그중 최소 길이를 고르자"로 접근했습니다. 그래서 `containers`에 경로를 쌓고, `dfs`로 경로를 수집하고, `Math.min(cnt, size)`로 최소를 고르려 했습니다. 예전에 백트래킹으로 경우의 수를 조합하던 관성이 그대로 나온 것입니다.

문제는 **"최단"을 "모든 경로 중 최소"로 읽은 것**입니다. BFS는 경로를 하나도 모으지 않고도 최단을 줍니다. 파동이 거리 순서로 퍼지기 때문에, 목표에 **처음 닿은 순간**이 곧 최단이거든요. 이 성질을 놓치니 최단을 직접 "경로를 나열해서" 구하려 했고, 그 순간 방향을 잃었습니다.

게다가 BFS 큐를 세워 놓고 그 위에 경로 수집(`containers`/`dfs`)을 얹었습니다. 두 모델이 섞이면서 정작 BFS에 반드시 필요한 **visited/dist가 없었고**, 같은 칸을 계속 다시 큐에 넣어 큐가 영영 안 비는 무한 루프에 빠졌습니다.

가장 근본적인 막힘은 따로 있었습니다. **"큐에서 한 칸을 꺼내고 → 네 방향으로 → 그 방향으로 `nx += d` 하며 벽/막힘 전까지 쭉 미끄러지고 → 지나치는 미방문 칸에 dist를 적는다"**라는 데이터의 흐름이 머릿속에 그려지지 않았습니다. 이 3중 구조(큐 / for 방향 / while 진행)를 그림으로 갖고 있지 않아서, `nx += direction[0]`으로 한 칸씩 이어 나간다는 상상 자체를 못 했습니다. 옆의 `PROCESS.html`은 정확히 이 흐름을 눈으로 보라고 만든 것입니다.

## 핵심 사고 (왜 이렇게 푸는가)

이 풀이는 네 개의 씨앗에서 각 줄이 따라 나옵니다. 코드를 외우는 게 아니라 이 씨앗에서 다시 뽑아내는 것이 목표입니다.

첫째, **"최단 횟수 + 가중치 없음"이면 BFS입니다.** 모든 이동의 비용이 1로 똑같으니(한 번 미끄러지면 1), 거리 순으로 퍼지는 BFS가 최단을 보장합니다. 그래서 큐와 dist 배열을 준비합니다. (비용이 칸마다 다르면 그때는 우선순위 큐를 쓰는 Dijkstra로 넘어갑니다.)

둘째, **먼저 닿은 것이 최단입니다.** 파동은 거리 0인 시작에서 1, 2, 3… 순서로 번지므로, 어떤 칸에 처음 도달했을 때의 거리가 그 칸의 최단입니다. 그래서 dist에 **처음 쓸 때만 기록하고 다시는 건드리지 않습니다.** 이 "미방문일 때만 기록"이 곧 visited 역할을 겸해서, 같은 칸을 두 번 큐에 넣지 않게 하고 무한 루프도 막습니다. dist 하나가 "거리 기록"과 "방문 표시" 두 일을 동시에 합니다.

셋째, **이 문제의 한 끗은 "이웃"의 재정의입니다.** 보통 격자 BFS의 이웃은 인접한 4칸이지만, 여기서는 한 이동이 "막힐 때까지 미끄러지기"라서, 한 칸의 이웃은 네 방향으로 그은 직선 위의 모든 칸입니다. 그래서 각 방향마다 `while`로 `nx += direction[0]`, `ny += direction[1]`을 반복하며 벽이나 X를 만나기 전까지 나아가고, 지나치는 미방문 칸을 전부 dist+1로 적습니다.

넷째, **목표에 처음 닿으면 끝입니다.** 큐에서 목표 칸을 꺼내는 순간 그 dist를 반환합니다. 경로가 무엇이었는지는 알 필요가 없습니다 — 최단 "횟수"만 물었으니까요.

## 손으로 따라가기

실제로 헷갈렸던 입력 `[".X.", ".X.", "..."]`, 시작 `(0,0)`, 목표 `(0,2)`로 dist가 파동처럼 채워지는 과정입니다. `.`은 미방문(-1), 숫자는 그 칸의 dist입니다.

```
파동0        파동1        파동2        파동3
0 X .        0 X .        0 X .        0 X 3   <- 목표 (0,2) 처음 닿음 = 3, 종료
. X .        1 X .        1 X .        1 X 3
. . .        1 . .        1 2 2        1 2 2
```

- 파동0: 시작 `(0,0)=0`만. 오른쪽은 `(0,1)=X`라 막히고, 위/왼쪽은 격자 밖.
- 파동1: `(0,0)`에서 아래로 미끄러지며 `(1,0)`, `(2,0)`을 1로.
- 파동2: `(2,0)`에서 오른쪽으로 미끄러지며 `(2,1)`, `(2,2)`를 2로.
- 파동3: `(2,2)`에서 위로 미끄러지며 `(1,2)`, `(0,2)`를 3으로. 목표 `(0,2)`에 닿았으니 **3**.

큐가 꺼내지는 순서로 보면 파동 경계가 그대로 드러납니다: `(0,0) | (1,0) (2,0) | (2,1) (2,2) | (1,2) (0,2)`. 세로 막대가 거리 한 겹의 경계입니다.

## 뼈대 압축

```
dist 전부 -1 (미방문)
queue = [시작],  dist[시작] = 0
while 큐가 안 빌 때까지:
    curr = 큐에서 꺼냄
    if curr == 목표: return dist[curr]      // 처음 꺼낸 순간이 최단
    for 방향 in 상하좌우:
        nx, ny = curr + 방향
        while 격자 안이고 막히지 않았으면:     // 미끄러짐
            if dist[nx][ny] == -1:           // 미방문일 때만
                dist[nx][ny] = dist[curr] + 1
                큐에 (nx, ny) 넣기
            nx += 방향;  ny += 방향           // 같은 방향 다음 칸
return dist[목표]                            // 시작==목표면 0, 못 닿으면 -1
```

## 복잡도 분석

여기서 `n`은 격자 한 변의 길이입니다(칸은 총 `n^2`개, 제약상 `n <= 100`).

**시간 = O(n^3).** 유도해 보면, 각 칸은 dist 덕분에 처음 도달할 때 딱 한 번만 큐에 들어가고 한 번만 꺼내집니다. 그래서 꺼내지는 칸은 최대 `n^2`개입니다(바깥 while). 한 칸을 꺼낼 때마다 네 방향으로 미끄러지는데, 한 방향의 미끄러짐은 최대 `n`칸을 지납니다(안쪽 while). 그래서 칸당 비용이 `4 * n = O(n)`이고, 전체는 `n^2 * O(n) = O(n^3)`입니다. `n=100`을 대입하면 약 `10^6(1,000,000)`번이라, 자바가 초당 약 `10^8`번을 처리하는 걸 감안하면 넉넉히 통과합니다.

**공간 = O(n^2).** dist 배열이 `n^2`칸을 차지하고, 큐도 최악에 모든 칸이 한 번씩 들어갈 수 있어 `O(n^2)`입니다.

참고로 경로를 전부 나열하는 DFS 백트래킹으로도 정답은 나오지만, 그 비용은 단순 경로의 수에 비례해 **지수 시간**입니다(경로 수가 칸 수에 지수적으로 늘어남). `n=100`에서는 감당이 안 됩니다. 그래서 실전 답은 BFS입니다 — 백트래킹은 "모든 경로"를 훑고, BFS는 "칸별 최단"만 한 번씩 채웁니다.

## 패턴 전이

같은 뼈대가 나오는 곳:

- **Rotting Oranges**(썩는 오렌지): 같은 파동 BFS인데, 시작점이 여럿(처음부터 썩은 칸 전부를 큐에 넣고 시작)이고 이웃이 인접 4칸입니다. "몇 번째 파동인가 = 최소 분"입니다. Castle에서 미끄러짐만 빼면 이 골격입니다.
- **미로 최단 거리, 섬까지의 거리, 다중 소스 확산**: 전부 "격자 위 최단/확산 = BFS로 dist 채우기"의 변주입니다. `for(방향)` 안이 인접 4칸이냐 미끄러짐이냐만 다릅니다.

한 층 아래의 공통 원리는 **"겹치는 부분문제는 나열하지 말고 상태별로 한 번만 기록·재사용한다"**입니다. 이건 Davis' Staircase(계단 오르기)에서 만난 것과 같은 원리입니다. 거기서는 "계단 오르는 모든 순서"를 나열하면 지수였고, "남은 칸이라는 상태별로 한 번만"(메모이제이션/DP) 접으니 선형이 됐습니다. Castle도 "모든 경로"를 나열하면 지수인데, "칸이라는 상태의 최단 거리를 한 번만"(BFS) 채우니 다항식이 됩니다. 병은 같고(중복 나열의 지수 폭발), 처방이 갈립니다 — **상태가 비순환이면 DP(고정 순서로 채움), 순환 그래프면 BFS(큐가 거리 순서를 실시간으로 만들어 줌)**. 격자는 왔다갔다 하는 순환이 있어서 BFS입니다.

## 코드에서 배운 것

- **`nx += direction[0]` 로 같은 방향을 이어 나간다**: 방향 벡터 `{-1,0}`, `{1,0}`, `{0,-1}`, `{0,1}`을 미리 배열로 두고, 한 방향으로 계속 더하면 그 직선을 훑습니다. "미끄러짐"이라는 추상적인 말이 결국 `while` 안에서 방향 벡터를 반복해 더하는 것이라는 걸, 이 코드로 처음 손에 익혔습니다. 방향을 배열로 두는 이 패턴은 모든 격자 문제에서 재사용됩니다.
- **dist 하나가 두 일을 겸한다**: 거리 기록과 방문 표시를 따로 둘 필요 없이, `dist[x][y] == -1`(미방문)일 때만 기록하면 됩니다. 별도 `visited` 배열을 안 만들어도 되는 이유입니다.

## 암기 카드
