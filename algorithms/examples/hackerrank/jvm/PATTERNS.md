# 문제를 코드로 바꾸는 사고 흐름과 패턴 카드

이 문서는 어떤 문제든 **문제 문장을 코드로 바꾸는 사고 흐름**을 붙잡기 위한 것입니다. 문제를 읽고 무엇을 내야 하는지 확인한 뒤, 그 결과를 만들려면 데이터를 어떤 순서로 어떻게 다뤄야 하는지 가늠하고, 그 흐름을 담을 자료구조를 고르고, 값에 의미를 주고, 불변식과 점화식으로 "왜 맞는가"를 닫고, 마지막에 코드 골격으로 받아쓰는 — 그 순서를 한 곳에 모읍니다.

세 문서가 역할을 나눠 같은 목표를 봅니다.

- 이 문서(PATTERNS): 문제를 코드로 바꾸는 **손에 잡히는 사고 순서 + 패턴 카드(움직임·골격·불변식) + 반복하는 실수**. 책상에서 바로 꺼내 쓰는 전술 자산.
- [problem_solving_growth.md](../../../problem_solving_growth.md): 같은 사고를 더 긴 서사와 여러 예제로 풀어 둔 **일반 뼈대**. 이 문서의 압축을 천천히 이해하고 싶을 때.
- [problem_solving_diagnosis.md](../../../problem_solving_diagnosis.md): 그 뼈대에서 **내가 실제로 이탈한 지점의 근본 원인**과 교정 훈련.

한 문장으로 외울 것부터 두겠습니다. 도구 이름(큐·힙·DP)을 맞히는 게임이 아니라, **무엇이 움직이고, 언제 답이 확정되고, 그 값을 어떤 순서로 채우는가**를 문장으로 닫는 게임입니다. 그 세 가지가 서면 자료구조와 코드는 뒤따라옵니다.

## 1. 사고 흐름: 문제 문장에서 코드까지

해설은 "이 문제는 스택입니다"로 시작하지만, 실제로 풀 때 머릿속은 "무엇을 들고 있어야 하지? 언제 답이 정해지지?"라는 흐릿한 질문에서 출발합니다. 이 간극을 메우는 것이 아래 순서입니다. 순서를 밟는 목적은 하나입니다 — 감으로 자료구조부터 고르지 않고, **결과에서 거꾸로 내려와** 자료구조와 코드가 필연이 되게 만드는 것입니다.

압축하면 growth 문서의 `답-확-반-상-질`입니다.

```text
답: 무엇을 반환하거나 세거나 최소/최대로 만드나?
확: 그 답의 일부는 언제 진짜로 확정되나?
반: 반복문 한 바퀴는 무엇을 하나?
상: 아직 확정되지 않아 들고 있어야 하는 것은 무엇인가?
질: 매번 느리게 묻는 질문은 무엇이고, 그 질문을 빠르게 답할 도구는 무엇인가?
```

> 막히면 "이 알고리즘을 모른다"로 가지 말고, `답-확-반-상-질` 중 무엇이 아직 말로 안 닫혔는지 짚는다. 대부분의 막힘은 도구를 몰라서가 아니라 확·반·상 중 하나가 비어서다.

이 다섯 칸을 실제로 코드까지 밀고 가면 여덟 걸음이 됩니다. 놓치기 쉬운 대표 문제 하나를 이 여덟 걸음에 그대로 얹어 보겠습니다 — LeetCode 402 **Remove K Digits**(자릿수 k개를 지워 가장 작은 수 만들기). 이 문제를 DFS와 `Math.min`, `long`으로 풀면 극단 케이스에서 깨지는데, 왜 깨지고 왜 스택이 답인지가 이 순서에서 드러납니다.

### 1) 조건과 내야 할 결과를 확정한다

먼저 무엇이 들어오고 무엇을 내야 하는지를 못 박습니다. 여기서 **제약(입력 크기·값 범위)** 을 반드시 소리 내어 읽습니다. 제약은 복잡도 상한과 오버플로 여부를 동시에 정하는 재료입니다.

Remove K Digits에서:

- 입력: 숫자 문자열 `num`(최대 100,000자리), 지울 개수 `k`.
- 조건: **정확히** k개를 지운다. 남은 자리의 순서는 유지한다.
- 결과: 만들 수 있는 가장 작은 수(문자열). 선행 0은 제거하고, 다 지워 비면 `"0"`.

여기서 결정적인 관찰 하나가 나옵니다. 정확히 k개를 지우면 **모든 후보의 자릿수가 `n-k`로 같습니다.** 길이가 같은 수는 "사전순으로 작다 = 숫자로 작다"이므로, 큰 수를 실제 숫자로 만들 필요가 전혀 없습니다. 이게 왜 중요한가는 제약이 답합니다 — 100,000자리는 `long`(최대 19자리)은 물론 어떤 정수 타입에도 안 들어갑니다. **숫자로 파싱하는 순간 깨집니다.** DFS + `long` 풀이가 극단 케이스에서 틀린 지점이 정확히 여기입니다. 결과는 자릿수 관계로만 정해지지, 값 계산으로 정해지지 않습니다.

### 2) 조건 안에서 데이터를 어떻게 처리할지 가늠한다

결과를 만드는 가장 느린 방법(기준선)부터 세웁니다. 기준선은 틀린 풀이가 아니라, 더 빠른 풀이가 왜 필요한지 알려 주는 출발점입니다.

가장 느린 방법은 지울 k개 위치의 모든 조합을 만들어 최솟값을 고르는 것입니다. 조합 수는 `C(n, k)`로 지수 폭발이라 100,000자리에서는 불가능합니다. DFS로 "이 자리를 지운다/남긴다"를 모두 뻗는 것도 같은 폭발입니다.

그래서 방향을 좁힙니다. 가장 작은 수는 **왼쪽 자리부터 최대한 작게** 만드는 것입니다. 앞자리 하나가 뒤 전부를 이기기 때문입니다(자리값이 압도적으로 큼). 그러니 "어디를 지울지 조합으로 탐색"이 아니라, "왼쪽부터 훑으면서 앞자리를 최대한 작게 유지"로 문제를 다시 씁니다.

### 3) 중간 단계를 설계한다

방향이 잡혔으면 한 번의 반복이 무엇을 하는지 정합니다. 여기서는 **왼쪽에서 오른쪽으로 한 자리씩** 보면서 결과를 쌓되, 새 자리가 올 때 "앞에 이미 세워 둔 더 큰 자리"를 지울지를 그 자리에서 결정합니다.

작은 예로 감을 잡습니다. `1234`에서 하나를 지운다면 `4`를 지웁니다(`123`). 반대로 `1243`에서 하나를 지운다면, 앞에서부터 보다가 `4 > 3`인 순간 — 더 작은 뒤 자리(`3`)를 막고 선 더 큰 앞자리(`4`)를 만나는 순간 — 그 `4`를 지웁니다(`123`). "더 큰 앞자리가 더 작은 뒤 자리를 막고 서 있으면 그 앞자리를 버린다"가 한 걸음의 핵심입니다.

### 4) 각 단계에서 데이터가 어떻게 흐르는지 그린다

한 걸음의 데이터 흐름을 손으로 굴립니다. 결과 버퍼가 있고, 새 자리 `ch`가 들어올 때 버퍼의 맨 끝(가장 최근에 넣은 자리)이 `ch`보다 크면 그 끝을 빼냅니다. 한 번 빼고 멈추지 않습니다 — 빼고 나서 드러난 새 끝이 또 `ch`보다 크면 그것도 뺍니다. 그래서 `if`가 아니라 `while`입니다.

`"1432219"`, k=3을 끝까지 굴리면(버퍼의 top은 오른쪽 끝):

```text
ch=1 -> 넣기                       -> k=3, 버퍼=1
ch=4 -> 1>4? 아니오, 넣기          -> k=3, 버퍼=14
ch=3 -> 4>3 빼기, 1>3? 아니오, 넣기 -> k=2, 버퍼=13
ch=2 -> 3>2 빼기, 1>2? 아니오, 넣기 -> k=1, 버퍼=12
ch=2 -> 2>2? 아니오(같음), 넣기     -> k=1, 버퍼=122
ch=1 -> 2>1 빼기(k->0), 넣기        -> k=0, 버퍼=121
ch=9 -> k=0 이라 건너뜀, 넣기       -> k=0, 버퍼=1219
```

큰 자리 `4, 3, 2`가 앞에서 차례로 밀려나 `1219`가 됩니다. 이 그림이 있으면 코드가 무엇을 시키는지 손에 잡힙니다.

### 5) 데이터를 원하는 대로 제어할 자료구조를 고른다

흐름을 보면 도구가 드러납니다. "뒤에서 넣고, 방금 넣은 것을 뒤에서 뺀다"는 **스택**입니다. 여기서는 `StringBuilder`가 스택 역할을 합니다(끝이 top). 반복해서 묻는 질문 "지금 맨 끝이 새 자리보다 큰가?"를 O(1)에 답하려고 스택을 붙인 것입니다.

자료구조는 이렇게 "반복 질문"에서 나옵니다. 감으로 고르는 게 아니라, 3장의 신호 표처럼 "매번 무엇을 빠르게 물어야 하는가"가 도구를 고릅니다.

### 6) 값에 의미를 부여한다

버퍼가 그냥 문자 더미가 아니라 **의미를 가진 상태**가 되게 이름을 붙입니다.

> 버퍼 = "지금까지 만들 수 있는 가장 작은 앞부분". k가 남는 한 비감소(non-decreasing)로 유지된다.

이 한 문장이 뒤의 모든 판단을 지탱합니다. growth 문서에서 말하는 "값 정의 한 문장"이자, 2장 도출 순서의 '소원'입니다. 값의 의미가 서야 "언제 지우고 언제 두는가"가 규칙의 번역이 됩니다.

### 7) 불변식·점화식·조건을 세운다

의미를 "항상 참"인 규칙으로 굳힙니다.

**불변식**: 버퍼는 k가 허락하는 한 비감소로 유지된다. 왜 이게 답이 되는가 — 자릿수가 같은 두 수는 앞자리가 작은 쪽이 작고, 더 작은 뒤 자리를 막고 선 더 큰 앞자리를 지우면 수가 가장 많이 줄기 때문입니다.

이 불변식에서 `while`의 조건 셋이 각각 하나씩 끌려 나옵니다.

- `0 < k`: 정확히 k개까지만 지운다.
- `버퍼가 비지 않음`: 지울 게 있을 때만.
- `top > ch`: 더 큰 앞자리만 지운다. `>=`가 아니라 `>`인 게 중요합니다 — 같으면(예: `"122"`의 두 `2`) 지워도 수가 안 작아지는데 k만 축냅니다(과삭제). 그래서 같으면 두고 넘어갑니다.

루프가 끝났는데 k가 남았다면? 끝까지 비감소였다는 뜻(지울 큰 앞자리가 없었음, 예: `1234`, `1199`). 비감소 수를 더 작게 만들려면 자리값이 가장 큰 **끝**을 자릅니다. 그래서 남은 k는 앞이 아니라 끝에서 뺍니다.

### 8) 골격으로 받아쓴다

이제 코드는 위 문장의 받아쓰기입니다.

```java
StringBuilder sb = new StringBuilder();
for (char ch : num.toCharArray()) {
    // 더 작은 뒤 자리를 막고 선 더 큰 앞자리를 버린다 (불변식 유지)
    while (0 < k && !sb.isEmpty() && sb.charAt(sb.length() - 1) > ch) {
        sb.deleteCharAt(sb.length() - 1);
        k--;
    }
    sb.append(ch);
}
while (0 < k) {                       // 끝까지 비감소였다면 끝에서 k개
    sb.deleteCharAt(sb.length() - 1);
    k--;
}
int start = 0;                        // 선행 0은 인덱스로 건너뛴다 (deleteCharAt(0) 반복은 O(n^2))
while (start < sb.length() && sb.charAt(start) == '0') start++;
String res = sb.substring(start);
return res.isEmpty() ? "0" : res;
```

이 문제가 알려 주는 한 끗은 도구 이름이 아니라 **신호**입니다.

> "가장 작게/크게 만들기" + "앞뒤 순서 유지" + "몇 개 제거/선택" -> 새 원소가 올 때 그보다 큰(작은) 앞 원소를 뒤에서 pop 하는 **단조 스택**. (자세한 카드는 4-I)

DFS + `Math.min` + `long`이 왜 졌는지 이제 두 겹으로 보입니다. 값으로 (1) 100,000자리는 `long`에 안 담겨 파싱이 깨지고, 구조로 (2) "지운다/남긴다"를 다 뻗는 조합이 지수입니다. 단조 스택은 각 자리를 많아야 한 번 넣고 한 번 빼서 O(n)입니다. 같은 목표를 놓고 느린 버전이 어디서 깨지는지를 본 것 — 이것이 브루트포스에서 최적해로 올라가는 감각입니다.

## 2. 표 채우기 도출 순서: 쌓는 값이 왜 맞나

값을 하나씩 채워 답을 만드는 문제 — BFS의 `dist`, DP의 `dp[]`, 다익스트라의 `dist`, 그리고 1장의 단조 스택까지 — 는 모두 "내가 쌓는 이 값이 최적인가? 내가 원한 값인가?"라는 불안을 부릅니다. 그 불안은 감으로 `+1`을 넣어서가 아니라, 아래 순서를 밟아 닫힙니다. 골격은 외운 게 아니라 이 순서를 문제에 대입해 **창발**한 결과입니다.

헷갈림의 뿌리는 서로 다른 세 행위를 한 순간에 하려는 데 있습니다. 갈라놓으면 풀립니다.

| 행위 | 무엇인가 | 지식이 필요한가 |
|---|---|---|
| **값** (무엇을 담나) | 소원 — 방법을 몰라도 적는다. 문제가 대개 그냥 준다 | 아니오 |
| **모양** (무엇으로 색인: 1D/2D/맵) | 정답이 있는 질문 — "한 상황을 콕 집는 좌표가 몇 개인가" | 예, 센다 |
| **맞음** (정말 그리 됐나) | 검증 — 불변식으로 맨 뒤에 얻는다 | 예, 확인한다 |

> 몰라서 못 쓰는 게 아니다. "원한다(소원)"를 먼저 적어야 방법을 찾을 방향이 생긴다. 확신은 맨 뒤에 온다.

BFS 최단거리(격자에서 시작점부터 목표까지 최소 걸음 수)를 예로 순서를 밟습니다. 화살표 뒤는 그 단계가 뽑아내는 데이터나 코드입니다.

1. **출력 한 문장** — 결국 뭘 내놓나. -> "시작에서 목표까지 최소 걸음 수".
2. **값의 소원** — 상황마다의 답으로 쪼갠다. -> `// dist[상황] = 시작에서 그 상황까지 최소 걸음`.
3. **좌표 세기(모양)** — "두 순간을 공정히 비교하려면 뭘 알아야 하나?" 그 개수가 차원. -> 위치 = (행, 열) = 2개 -> 2차원.
4. **그릇 타입** — 좌표가 조밀한 정수면 배열, 아니면(문자열·희소) 맵. -> `int[][] dist = new int[n][m]`.
5. **점화식(연산 강제)** — 한 상황 값을 이전/이웃 값으로 어떻게? `+1`/`min`/`max`는 2번 의미에서 역산. -> 한 칸 = 1걸음 -> `dist[이웃] = dist[현재] + 1`.
6. **닫힘 검사** — 같은 슬롯에 답이 다른 상황이 몰리나? 몰리면 좌표가 하나 빠진 것 -> 3으로 가 차원을 올린다(벽 K개 부수기면 `dist[r][c][k]`). 실패가 빠진 좌표를 알려 주니 미리 다 몰라도 된다.
7. **순서 장치(자료구조)** — 점화식 입력이 읽히는 시점에 이미 최종값이려면 어떤 순서로 채워야 하나? 그 순서를 만드는 게 자료구조. -> 거리 오름차순 -> **큐**. (가중치 있으면 힙, DAG면 위상순서)
8. **초기화** — 방법 없이 아는 값 + "미확정" 표식. -> `dist[시작] = 0; 나머지 -1; queue.add(시작)`.
9. **채우기 루프(불변식을 코드로)** — 꺼내 -> 점화식 -> 처음일 때만 확정 -> 등록. -> `if (dist[이웃] == -1) { dist = ... + 1; add; }`.
10. **검증** — 불변식 3박자(초기화에서 참 / 한 번 돌려도 참 / 끝나면 그게 답) + 2x2 손 트레이스. 어긋나면 값이 틀림 -> 5·9, 슬롯 충돌 -> 3·6, 순서 문제 -> 7로.

**데이터 흐름 한 컷**: 빈 `dist` -> `시작=0` 씨앗 -> 점화식이 이웃으로 `+1`씩 전파 -> 큐가 "가까운 것 먼저" 보장 -> 각 칸이 처음 닿을 때 확정 -> `dist[목표]`가 답.

이 순서는 BFS만의 것이 아닙니다. DP는 7번의 순서 장치가 큐 대신 "작은 인덱스 먼저 도는 for"이고, 다익스트라는 힙이며, 1장의 단조 스택은 소원이 "가장 작은 앞부분", 순서 장치가 "왼쪽부터 훑으며 pop"인 같은 족보입니다. 값 정의 한 문장(소원)과 순서 장치만 갈아 끼우면 됩니다.

## 4. 패턴 카드 (움직임 + 골격 + 불변식)

각 카드는 세 개를 한 몸으로 봅니다 — 데이터가 어떻게 **움직이는지**, 그걸 담는 **골격**, 그리고 그 골격이 왜 맞는지 지탱하는 **불변식**. `불변식:`은 그 자료구조가 항상 뜻하는 한 문장입니다. 이게 유지되면 답이 맞습니다.

### 4-A. BFS — 격자 최단 거리/횟수

문제: [HR Castle on the Grid](https://www.hackerrank.com/challenges/castle-on-the-grid/problem) · [PRG 게임 맵 최단거리](https://school.programmers.co.kr/learn/courses/30/lessons/1844) · [PRG 단어 변환](https://school.programmers.co.kr/learn/courses/30/lessons/43163) · [PRG 가장 먼 노드](https://school.programmers.co.kr/learn/courses/30/lessons/49189) · [LC 102 Binary Tree Level Order](https://leetcode.com/problems/binary-tree-level-order-traversal/)

움직임 — dist를 파동처럼 채운다. 목표에 처음 닿은 값이 최단:

```text
0 1 2     시작 0에서 한 겹씩 +1로 퍼짐. 큐(FIFO)라 가까운 것부터.
1 2 3     경로를 모으지 않는다 — dist만 채우면 답.
2 3 4
```

골격:

```java
int[][] dist = new int[n][m]; for (int[] row : dist) Arrays.fill(row, -1);
queue.add(start); dist[sr][sc] = 0;
while (!queue.isEmpty()) {
    cur = queue.poll();
    if (cur == goal) return dist[cur.r][cur.c];      // 처음 꺼낸 게 최단
    for (int[] d : DIRS) {                            // DIRS = 상하좌우
        nr = cur.r + d[0]; nc = cur.c + d[1];
        if (범위 && !막힘 && dist[nr][nc] == -1) {     // 넣기 전에 검사 + 표시
            dist[nr][nc] = dist[cur.r][cur.c] + 1; queue.add(new int[]{nr, nc});
        }
    }
}
```

함정: dist가 방문표를 겸한다(-1이면 미방문). 이동이 미끄러짐이면 4-C로.

**불변식**: 큐(FIFO) = 거리 오름차순 처리 -> 각 칸에 처음 닿는 순간 값이 곧 최단(다시 안 바뀜). `== -1` 가드가 "처음 = 최단"을 지키는 자물쇠. 이 값이 왜 맞는지 불안하면 2장 도출 순서로.

### 4-B. flood fill — 이어진 덩어리 크기/개수

문제: [HR Connected Cells in a Grid](https://www.hackerrank.com/challenges/connected-cell-in-a-grid/problem) · [LC 200 Number of Islands](https://leetcode.com/problems/number-of-islands/) · [PRG 네트워크](https://school.programmers.co.kr/learn/courses/30/lessons/43162)

움직임 — 찾은 칸이 다시 출발점(연쇄). 꺾어가며 이어진 것을 다 방문:

```text
1 1 0     (0,0)->이웃 (0,1),(1,1)->그 이웃 (1,2)... "이웃의 이웃의 이웃"
0 1 1     직선으로 긋는 게 아니라 연쇄로 퍼진다.
```

골격 (DFS 재귀 — 짧음, 기본으로 이걸):

```java
int flood(r, c) {
    if (범위밖 || visited[r][c] || 안채워짐) return 0;   // 가드의 집 (재귀는 여기 한 곳)
    visited[r][c] = true;
    int size = 1;
    for (int[] d : DIRS) size += flood(r + d[0], c + d[1]);  // 이웃은 그냥 부름 (미리 필터 불필요)
    return size;
}
// driver: for r, c: max = Math.max(max, flood(r, c));
```

골격 (BFS 큐 — 격자가 아주 커서 깊은 재귀가 걱정될 때):

```java
queue.add(seed); visited[seed] = true; int size = 0;
while (!queue.isEmpty()) { cur = poll(); size++;
    for (d : DIRS) { nr, nc; if (범위 && !visited[nr][nc] && 채워짐) { visited[nr][nc] = true; queue.add(new int[]{nr, nc}); } } }
```

함정(핵심): **가드 위치가 DFS/BFS 다르다** — DFS는 base case에서 거른다(부르기 전 필터 불필요·무해), BFS는 넣기 전에 거른다(필수, 안 하면 중복·무한). 한 곳에만. 0/벽은 visited 마크 불필요(조건이 이미 막음). 미끄러짐(4-C)과 헷갈리지 말 것 — flood엔 while 슬라이드가 없다.

**불변식**: `visited[c] == true` = "이미 센 칸". 각 칸이 정확히 1번만 세짐 -> size 정확, 무한루프 없음. (최적화가 아니라 도달·개수 문제 — 2장의 점화식/최소성 도출은 여기 안 씀.)

**바깥 중첩 for의 역할**: 씨앗 심기다 — 서로 안 이어진 덩어리가 여러 개라 각 덩어리에 한 번씩 불을 붙인다. 연결을 따라가는 건 flood가 한다(for는 꺾어 들어가지 못한다 — (1,2)는 (0,1)이나 (1,1)에서 꺾어야 닿는다). 시작점이 하나로 주어지면(Castle) 바깥 for는 불필요.

### 4-C. 미끄러짐(룩) — 격자 최소 이동

문제: [HR Castle on the Grid](https://www.hackerrank.com/challenges/castle-on-the-grid/problem)

움직임 — 한 방향으로 막힐 때까지 쭉, 그 직선 위 아무 칸에나 설 수 있음:

```text
. X .     (0,0)에서 우는 X로 막힘, 아래로 쭉 -> (1,0),(2,0). 한 번에 여러 칸.
. X .     그래서 이웃 = 인접 한 칸이 아니라 '직선 위 모든 칸'.
. . .
```

골격 (4-A와 같은 BFS인데 방향마다 while 하나 더):

```java
for (int[] d : DIRS) {
    nr = cur.r + d[0]; nc = cur.c + d[1];
    while (범위 && !막힘) {                          // 미끄러짐 = while
        if (dist[nr][nc] == -1) { dist[nr][nc] = dist[cur.r][cur.c] + 1; queue.add(new int[]{nr, nc}); }
        nr += d[0]; nc += d[1];                       // 같은 방향으로 계속
    }
}
```

함정: 4-B(flood)엔 이 while이 없다. 앞 문제의 while을 flood에 옮기다 꺾인 연결을 놓치기 쉽다.

**불변식**: 4-A와 동일(큐 = 거리 오름차순, 처음 닿은 값 = 최단). 달라진 건 "이웃"의 정의뿐 — 인접 한 칸이 아니라 직선 위 모든 칸. 도출 순서도 4-A와 같고 5번(이웃 규칙)만 바뀐다.

### 4-D. 힙 — 최솟값을 반복해 꺼내 처리

문제: [HR Jesse and Cookies](https://www.hackerrank.com/challenges/jesse-and-cookies/problem) · [PRG 더 맵게](https://school.programmers.co.kr/learn/courses/30/lessons/42626) · [PRG 디스크 컨트롤러](https://school.programmers.co.kr/learn/courses/30/lessons/42627) · [PRG 이중우선순위큐](https://school.programmers.co.kr/learn/courses/30/lessons/42628)

움직임 — 전체 정렬을 안 하고 매번 극값만:

```text
넣기 5,1,3  ->  꺼내면 1,3,5 (항상 최솟값이 꼭대기). 넣고 꺼낼 때마다 O(log n).
```

골격 (목표의 부정을 루프 조건으로):

```java
PriorityQueue<Long> pq = new PriorityQueue<>();   // long! 결합값이 int(21억) 넘음
for (int x : a) pq.add((long) x);
int ops = 0;
while (pq.peek() < k) {           // 목표 "최소 >= k"의 부정을 루프 조건에 (불변식)
    if (pq.size() < 2) return -1; // 섞을 둘이 없으면 불가
    long x = pq.poll(), y = pq.poll();
    pq.offer(x + 2 * y); ops++;
}
return ops;                       // 루프 0회 = 이미 만족 = 0
```

함정: max-heap은 `new PriorityQueue<>(Comparator.reverseOrder())`. 합/곱이 21억 넘으면 long.

**불변식**: 힙 꼭대기 = 현재 최소. 탐욕이 맞는 근거는 "가장 작은 둘을 합치는 게 항상 최선"(교환논법). 루프 불변: `peek() < k`인 동안만 도니 끝나면 전부 >= k.

### 4-E. DP/메모 — 겹치는 부분문제

문제: [HR Davis' Staircase](https://www.hackerrank.com/challenges/ctci-recursive-staircase/problem) · [PRG 멀리 뛰기](https://school.programmers.co.kr/learn/courses/30/lessons/12914) · [PRG 정수 삼각형](https://school.programmers.co.kr/learn/courses/30/lessons/43105) · [PRG 등굣길](https://school.programmers.co.kr/learn/courses/30/lessons/42898) · [PRG 땅따먹기](https://school.programmers.co.kr/learn/courses/30/lessons/12913) · [PRG N으로 표현](https://school.programmers.co.kr/learn/courses/30/lessons/42895)

움직임 — 나열하면 지수, 상태별 1회 저장하면 선형:

```text
f(n)=f(n-1)+f(n-2)+f(n-3). 여러 경로가 f(3)을 또 계산 -> 지수 폭발.
한 번 계산해 dp[3]에 저장, 다음엔 꺼내 쓴다.
```

골격 (bottom-up 표 — 제일 깔끔):

```java
int[] dp = new int[n + 1];
dp[0] = 1;
for (int i = 1; i <= n; i++) {
    dp[i] = dp[i - 1];
    if (i >= 2) dp[i] += dp[i - 2];
    if (i >= 3) dp[i] += dp[i - 3];
}
return dp[n];
```

골격 (top-down 메모 — 재귀가 자연스러울 때):

```java
Integer[] memo = new Integer[n + 1];
int f(int i) {
    if (i == 0) return 1; if (i < 0) return 0;
    if (memo[i] != null) return memo[i];
    return memo[i] = f(i - 1) + f(i - 2) + f(i - 3);
}
```

함정 트리거: "같은 인자로 여러 번 불림 + 답이 경로가 아니라 인자에만 의존" -> 캐시하라.

**불변식**: `dp[i]` = i까지의 최적/개수. 순회 순서(작은 i 먼저)가 dp[i]가 참조하는 것들(i-1, i-2, i-3)이 이미 확정임을 보장 — 4-A의 "큐"가 하던 순서 보장을 여기선 for 순서가 한다. **도출은 2장과 같은 족보**: 상태 = dp 인덱스, 순서 장치 = 순회 순서(또는 위상정렬).

### 4-F. 이분탐색 — 정렬된 것에서 반씩 버림

문제: [PRG 입국심사](https://school.programmers.co.kr/learn/courses/30/lessons/43238) (답을 이분탐색 — "시간 T에 다 처리 가능?"을 판정으로)

움직임:

```text
[1,3,5,7,9]서 7: 가운데 5<7 -> 오른쪽만 -> 가운데 7 = 찾음. 매번 절반 O(log n).
```

골격:

```java
int lo = 0, hi = n - 1;
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;         // (lo+hi)/2는 오버플로 위험
    if (a[mid] == target) return mid;
    else if (a[mid] < target) lo = mid + 1;
    else hi = mid - 1;
}
return -1;
```

**불변식**: "답이 있다면 반드시 `[lo, hi]` 안에 있다". 매 반복 절반을 버려도 이게 유지되므로 안전. 종료(lo > hi) = 구간이 비었으니 없음.

### 4-G. 슬라이딩 윈도우 — 연속 구간, 두 포인터

문제: [LC 3 Longest Substring Without Repeating](https://leetcode.com/problems/longest-substring-without-repeating-characters/) · [HR Fraudulent Activity Notifications](https://www.hackerrank.com/challenges/fraudulent-activity-notifications/problem) (창 + 계수 배열)

움직임:

```text
[2,1,5,1,3] 길이3 최대합: right로 더하고, 창이 3 넘으면 left 것을 뺀다. O(n).
```

골격:

```java
int sum = 0, best = Integer.MIN_VALUE;
for (int r = 0; r < n; r++) {
    sum += a[r];
    if (r >= k) sum -= a[r - k];          // 창을 벗어난 왼쪽 빼기
    if (r >= k - 1) best = Math.max(best, sum);
}
```

**불변식**: `sum` = 지금 창(최근 k개)의 합. r이 진행할 때 더하고 벗어난 왼쪽을 빼는 짝이 이 한 문장을 유지 -> 매 위치에서 O(1)로 정답.

### 4-H. 스택 — 최근 것부터 / 짝 맞추기

문제: [HR Balanced Brackets](https://www.hackerrank.com/challenges/balanced-brackets/problem) · [PRG 올바른 괄호](https://school.programmers.co.kr/learn/courses/30/lessons/12909)

움직임:

```text
"([)": '(' push, '[' push, ')' pop해 짝 확인 -> 짝은 '['이라 불일치. 끝에 비면 정상.
```

골격:

```java
Deque<Character> st = new ArrayDeque<>();
for (char c : s) {
    if (여는 괄호) st.push(c);
    else { if (st.isEmpty() || !맞짝(st.pop(), c)) return false; }
}
return st.isEmpty();
```

**불변식**: 스택 = "아직 안 닫힌 여는 괄호들"(가장 최근이 맨 위). 닫는 걸 만나면 반드시 맨 위와 짝이어야 함 -> 끝에 비면 전부 짝 맞음.

### 4-I. 단조 스택 — 다음 큰/작은 값, 사전순 최소

문제: [LC 402 Remove K Digits](https://leetcode.com/problems/remove-k-digits/) · [PRG 큰 수 만들기](https://school.programmers.co.kr/learn/courses/30/lessons/42883) · [LC 739 Daily Temperatures](https://leetcode.com/problems/daily-temperatures/) · [PRG 뒤에 있는 큰 수 찾기](https://school.programmers.co.kr/learn/courses/30/lessons/154539) · [PRG 주식가격](https://school.programmers.co.kr/learn/courses/30/lessons/42584) · [LC 496 Next Greater Element](https://leetcode.com/problems/next-greater-element-i/)

일반 스택(4-H)이 "짝이 맞나"를 보는 반면, 단조 스택은 스택 안이 **항상 정렬된 상태(단조 증가 또는 감소)로 유지**되게 새 원소가 올 때 규칙을 어기는 대기자를 pop 합니다. 두 얼굴이 있습니다.

얼굴 1 — **다음 큰/작은 값**(Daily Temperatures, Next Greater). 아직 짝을 못 만난 인덱스를 쌓고, 새 값이 그 대기자를 이기면 그 순간이 대기자의 답:

```text
스택 = 아직 자기보다 큰 값을 못 만난 인덱스들 (바닥->위로 값이 감소).
새 값 a[i]가 스택 top의 값보다 크면, top은 방금 "다음 큰 값"을 만난 것 -> pop 하며 답 확정.
```

```java
int[] ans = new int[n];
Deque<Integer> st = new ArrayDeque<>();       // 값이 아니라 인덱스를 쌓는다
for (int i = 0; i < n; i++) {
    while (!st.isEmpty() && a[i] > a[st.peek()]) {
        int j = st.pop();
        ans[j] = i - j;                        // i가 j의 다음 큰 값 (거리)
    }
    st.push(i);
}
```

얼굴 2 — **사전순 최소/최대**(Remove K Digits, 큰 수 만들기). 결과 버퍼를 스택으로 쓰고, 새 원소가 오면 "뒤를 막고 선 더 큰(작은) 앞 원소"를 예산(k)이 허락하는 한 pop. 1장에서 끝까지 유도한 그 골격입니다:

```java
StringBuilder sb = new StringBuilder();       // StringBuilder가 스택 (끝이 top)
for (char ch : num.toCharArray()) {
    while (0 < k && !sb.isEmpty() && sb.charAt(sb.length() - 1) > ch) {
        sb.deleteCharAt(sb.length() - 1); k--; // 더 큰 앞자리를 버려 수를 줄인다
    }
    sb.append(ch);
}
while (0 < k) { sb.deleteCharAt(sb.length() - 1); k--; }   // 남으면 끝에서 (비감소였다는 뜻)
```

함정: pop 조건이 `>`인지 `>=`인지 문제마다 다르다 — 같은 값을 어떻게 다룰지(과삭제 방지 vs 최신 유지)가 정한다. 값이 아니라 인덱스를 쌓아야 거리·구간을 복원할 수 있는 문제가 많다. "가장 작게/크게 + 순서 유지"면 얼굴 2, "각 원소의 다음 큰/작은 것"이면 얼굴 1.

**불변식**: 스택은 항상 단조(증가 또는 감소)로 유지된다. 왜 pop이 안전한가 — 스택에 먼저 든 a와 나중 든 b가 공존한다면, b가 들어올 때 규칙이 a를 안 꺼냈다는 뜻이므로 둘의 관계는 이미 정해져 있다. 그 "공존이 강제하는 관계"가 곧 단조성이고, 새 원소가 그걸 깨는 대기자만 정확히 걷어낸다. (관계로 증명하는 법은 growth 문서의 "구체 시뮬은 발견, 기호 시뮬은 증명".)

### 4-J. 백트래킹 — 모든 조합/순열 생성

문제: [PRG 타겟 넘버](https://school.programmers.co.kr/learn/courses/30/lessons/43165) · [PRG 소수 찾기](https://school.programmers.co.kr/learn/courses/30/lessons/42839) (순열 생성) · [PRG 모의고사](https://school.programmers.co.kr/learn/courses/30/lessons/42840) (완전탐색)

움직임:

```text
[1,2,3] 조합: 1 고름 -> {1,2},{1,3} -> 1 빼고(되돌리기) 2 고름 -> {2,3}...
```

골격:

```java
void rec(int start, List<Integer> path) {
    record(path);                        // 또는 path.size() == k일 때만
    for (int i = start; i < n; i++) {
        path.add(a[i]);
        rec(i + 1, path);                // 조합: i+1(지난 건 안 봄). 순열이면 for 0..n + used[]
        path.remove(path.size() - 1);    // 되돌리기 = 백트래킹의 심장
    }
}
```

함정: 순서 무관(조합)이면 start로 앞으로만, 순서 중요(순열)면 used[]로 전체에서 쓴 것만 제외.

**불변식**: `path` = 지금까지 고른 부분해. `add -> 재귀 -> remove` 짝이 "형제 가지로 넘어가기 전 상태 원복"을 보장 -> 모든 조합을 정확히 1번씩, 오염 없이.

## 5. 격자 3형제 구별

BFS 계열 세 카드(4-A / 4-B / 4-C)가 헷갈릴 때:

| 유형 | 이웃 | 무엇을 | while? |
|---|---|---|---|
| flood(4-B) | 인접 칸, 찾은 칸 재출발 | 이어진 칸 수 | 없음 |
| 최단 BFS(4-A) | 인접 칸, dist 파동 | 최소 거리/횟수 | 없음 |
| 미끄러짐(4-C) | 직선 위 모든 칸 | 최소 이동 횟수 | **있음** |

**BFS vs DFS**: 최단이면 반드시 BFS. 그냥 다 방문/개수면 아무거나(DFS 재귀가 짧음).

**씨앗 심는 세 가지**: 시작점 하나 주어짐(Castle) = 바깥 for 불필요 / 덩어리 여러 개(Connected Cells) = 중첩 for로 씨앗 / 시작점 여러 개 동시(썩는 오렌지류) = 전부 큐에 넣고 시작.

## 6. 복잡도 세는 법

코딩 전에 이 순서로 소리 내어 셉니다.

1. 변수 정의(n, m이 뭔지)
2. 바깥 루프 횟수 x 반복당 비용
3. 곱(중첩)/합(순차) 정리, 지배항
4. 제약 대입 어림수(자바 초당 약 10^8, ~은 "약"). 격자면 대개 O(n*m).

**재귀·DFS·메모/DP는 호출 트리를 세지 말고 상태 장부를 세라** — visited/캐시가 있으면 각 상태의 본문은 딱 1번 돌고, 나머지 호출은 O(1)로 반사됩니다.

> 복잡도 = 서로 다른 상태 수 x 상태 하나의 본문 비용

- flood/DFS 격자: 칸 n*m개 x 이웃 4 = O(n*m). 말로: "각 칸이 visited로 최대 1번 방문, 방문당 4방향".
- 메모 재귀(Davis): 상태 n+1개 x 덧셈 3번 = O(n). 캐시 없으면 가지 3개가 지수로 폭발.
- bottom-up DP: 표 크기 x 칸당 비용 (for가 장부를 그대로 노출해 세기 쉬움 — 메모 재귀도 같은 장부).
- 단조 스택: 각 원소가 많아야 한 번 push, 한 번 pop -> 총 연산 <= 2n = O(n). "한 번 나간 건 다시 안 들어온다"가 근거.

## 7. 타입과 오버플로

값·합·곱의 최대가 int(약 21억, 2,147,483,647)를 넘으면 `long`. mod 10^10 규모면 `long`. 합/곱이 보이면 코딩 전에 최댓값을 어림합니다(21억 근처면 그냥 long).

또 하나의 함정은 **아예 정수 타입에 안 들어가는 경우**입니다. `long`도 최대 19자리라, 100,000자리 숫자 문자열(Remove K Digits)은 파싱하는 순간 깨집니다. 이때는 값이 아니라 **자릿수·순서 관계로만** 답을 정합니다(1장 참고).

## 8. 반복하는 실수

문제를 풀며 실제로 반복해 걸린 실수들입니다. 무는 순서대로: 읽기 -> 접근 -> 구현. 각 실수의 뿌리는 [problem_solving_diagnosis.md](../../../problem_solving_diagnosis.md)에서 원인까지 다룹니다.

| 실수 | 실제 사건 | 처방 |
|---|---|---|
| **문제 오독** — 이동/연결 규칙 넘겨짚기 | Castle: 미끄러짐을 "한 칸 이동"으로 오해한 채 구현 | 코딩 전 샘플 1개를 문제 규칙대로 손으로 굴려 기대 출력 재현 |
| **직전 모델 전이** | Castle의 while 슬라이드를 Connected Cells(flood)에 옮겨 꺾인 연결을 놓침 | 새 문제 = 이동/연결 규칙을 백지에서 새로 읽기. 격자면 5장 표로 3형제 중 무엇인지 먼저 판정 |
| **루프 역할 혼동** | Connected Cells: "중첩 for로 다 방문하면 되지 않나"로 샘 | 중첩 for = 씨앗 심기, 연결 추적 = flood. for는 꺾어 들어가지 못한다 |
| **스친 정답 승격 실패** | Davis: 주석에 "caching?"까지 써놓고 지나감. Remove K Digits: "4>3이면 4 제거"까지 써놓고 while로 못 밀어붙임 | 번뜩이면 거기서 멈춰 소리 내기: "방금 생각이 답 아닌가?" 비용을 따진 뒤에 버린다 |
| **최적화 구조가 안 떠오름** | Davis: 나열(재귀)까지 하고 캐시로 못 넘어감. Remove K Digits: DFS+min까지 갔지만 단조 스택으로 못 올라감 | 신호 고정: "같은 인자로 또 불림 + 답이 인자에만 의존" -> 상태 저장(4-E). "가장 작게 + 순서 유지 + 몇 개 제거" -> 단조 스택(4-I). 나열이 먼저, 구조는 그 다음 |
| **추상적으로만 생각하다 시간 소모** | Castle: dist[][] 구조가 안 떠오름 — 데이터 흐름이 머릿속에 없었음 | 막히면 즉시 2x2~3x3 예제로 자료구조 상태를 손으로 2단계 그리기. 값으로 생각하고, 구조가 필요하면 2장 도출 순서로 |
| **케이스 열거 불완전** | Sherlock: B(최대 빈도 -1)는 떠올렸는데 A(빈도 1 글자 통째 삭제)를 놓칠 뻔 | 케이스 나눴으면 1회 강제 되묻기: "이 조작이 가능한 *다른* 형태는 없나?" 연산 효과를 식으로 쓰고 경계값에서 분기를 유도 |
| **사소한 분기에 생각 틀어짐** | Connected Cells: "0도 visited 마크? continue?"에서 흔들림 | 정확성에 영향 없으면 아무거나 골라 선언하고 진행: "어느 쪽이든 되니 A로 갑니다" |
| **오버플로/타입 미스** | Jesse: 결합값 x+2y가 int 초과해 WA. Remove K Digits: 100,000자리를 long으로 파싱하면 깨짐 | 합/곱이 보이면 최댓값 어림 먼저(7장). 타입에 안 들어가면 값 대신 순서·자릿수 관계로 |
| **복잡도 나중에 세기** | 여러 번 — 짜고 나서 통과 여부 걱정 | 코딩 전 복잡도 세기(6장)를 소리 내는 것으로 고정 |

상시 리마인더:

- **최단 = dist 채우기**, 경로 수집이 아니다.
- **값이 안 맞으면 그 카드 불변식부터**, 표-채우기면 2장 도출 순서로. "뭘 증가시키지"가 막히면 소원·좌표·점화식이 안 선 것 — 감으로 +1 넣지 말 것.

## 9. 막혔을 때 되돌아갈 자리

막힘은 재능 문제가 아니라 대개 한 칸이 안 닫힌 것입니다. 순서대로 되돌아갑니다.

1. **`답-확-반-상-질` 중 뭐가 비었나** — "이 알고리즘을 모른다"로 가기 전에 다섯 칸을 짚는다. 대부분 확·반·상 중 하나다.
2. **작은 예제를 손으로 생산한다** — 읽지 말고 만든다. n=2, 3에서 자료구조 상태를 2~3단계 그리면 구조가 눈에 잡힌다(뿌리 1의 교정).
3. **값 정의 한 문장을 쓴다** — `dist[상황] = ...`, `dp[i] = ...` 처럼 소원부터. 값이 서야 점화식과 조건이 따라온다.
4. **브루트포스라도 짠다** — 느려도 도는 코드가 우아한 빈 화면보다 낫다. 기준선이 최적화의 필요를 알려 준다.
5. **접근을 버릴 땐 이유 한 문장** — "A를 버리는 이유는 X"를 말하면, 그 순간 반례가 보인다("for가 (1,2)로 꺾어 들어가나?").
