# 패턴 결정 가이드 — 접근이 안 잡히거나 도중에 흔들릴 때 방향 잡기

> 이 문서는 **"무엇으로 풀지"**를 정하는 곳. 문법은 `cheatsheet`, 멘탈·막힘 대응은 `PLAYBOOK`.
> 실전에서 접근이 안 서거나 도중에 흔들리면 1번 표부터 본다.

## 1. 신호 -> 도구 (문제에서 이 말이 보이면 이걸 꺼낸다)

| 문제 신호 | 도구 | 핵심 자료구조 |
|---|---|---|
| 최단 거리/최소 횟수 + 가중치 없음 | BFS | 큐 + dist[][] |
| 연결 덩어리/영역/전부 방문/개수 | flood fill (BFS든 DFS든) | 큐 or 재귀 + visited |
| 가장 작은/큰 것을 반복해 꺼냄 | 힙 | PriorityQueue |
| 같은 부분문제를 다시 계산(겹침) | DP/메모(비순환) or BFS(순환) | dp[] or dist |
| 정렬된 것에서 찾기/경계 조건 | 이분탐색 | lo/mid/hi |
| 연속 구간/창(window) | 슬라이딩 윈도우 | 두 포인터 |
| 최근 것부터/짝 맞추기 | 스택 | ArrayDeque |
| 순서대로 처리(먼저 온 것 먼저) | 큐 | ArrayDeque |
| 모든 조합·순열 생성 | 백트래킹 | 재귀 + mark/unmark |

## 2. 격자 3형제 — 헷갈리지 마라 (이번에 여기서 왔다갔다 함)

셋 다 격자지만 "이웃"과 "무엇을 세나"가 다르다. **지문의 '이동/연결 규칙'을 정확히 읽어 구별.**

| 유형 | 이웃 정의 | 무엇을 구하나 | 예 |
|---|---|---|---|
| flood(덩어리) | 인접 칸, 찾은 칸이 다시 출발점 | 이어진 칸 수/개수 | Connected Cells, Number of Islands |
| 최단 BFS | 인접 칸, 파동으로 dist 채움 | 최소 거리/횟수 | 미로 최단 |
| 미끄러짐(룩) | 한 방향 직선 위 모든 칸(while) | 최소 이동 횟수 | Castle on the Grid |

**함정(실제로 겪음)**: 직전 문제의 이동 모델을 그대로 옮기지 마라. Castle의 `while 미끄러짐`을 Connected Cells에 쓰면 꺾인 연결(예: (0,0)->(0,1)->(1,2))을 놓친다.

## 3. BFS vs DFS — 어떻게 고르나 (이번 고민)

- **최단 거리/횟수가 필요하면 -> 반드시 BFS** (DFS는 최단 보장 못 함).
- **그냥 다 방문/개수/존재만이면 -> 아무거나.** DFS 재귀가 짧고, 깊은 재귀가 걱정되는 아주 큰 입력이면 BFS 큐.
- 둘은 같은 칸을 방문 순서만 다르게 훑는다(BFS = 겹으로, DFS = 깊이로).
- 이번: Connected Cells는 "개수"만 -> DFS 재귀(짧음). Castle은 "최단" -> BFS.

## 4. visited / 가드 어디에 두나 (이번 고민 — 한 곳에 정하면 안 흔들림)

- **재귀(DFS)**: 가드는 함수 첫 줄(base case)에 — `경계 밖 || visited || 조건 안 맞음 -> return`. 그러면 driver는 모든 칸에 그냥 호출(자기가 알아서 0 반환). driver의 `if(visited) continue`는 있어도/없어도 됨(중복이지 무해).
- **큐(BFS)**: 큐에 **넣기 전에** visited 검사 + 표시. 넣고 나서 검사하면 같은 칸이 중복 들어가 무한 루프.
- **0/벽 칸은 visited 안 해도 됨** — 조건 검사(isFilled/막힘)가 이미 막으니까. visited는 "채워진 칸을 두 번 세지 않기" 용도.
- **규칙: 가드의 집을 하나로 정하라** (재귀 = base case, 큐 = 넣기 전). 두 곳에 흩으면 "여기도 해야 하나?"로 흔들린다.

## 5. 몸통 골격 (외워두면 빈 화면에서 바로 시작)

격자 순회:
```
for (r = 0..n) for (c = 0..m) { ... }
```
BFS (최단/파동):
```
dist 전부 -1; queue=[시작]; dist[시작]=0
while (큐 안 빔): cur=꺼냄
  for (dir): 이웃 계산; if (유효 && 미방문) { dist[이웃]=dist[cur]+1; enqueue }
```
DFS flood (덩어리 크기):
```
int flood(r,c):
  if (경계 밖 || visited || 조건X) return 0
  visited[r][c]=true; size=1
  for (dir): size += flood(이웃)
  return size
```
백트래킹 (모든 경우):
```
mark; rec(...); unmark   // 되돌리기(unmark)가 핵심 = DFS
```

## 6. 복잡도 4박자 (약점 — 매번 이 순서로 소리 내어)

1. 변수 정의: n, m이 각각 뭔지.
2. 바깥 루프 횟수 x 반복당 비용.
3. 곱(중첩)/합(순차), 지배항만 남김.
4. 제약 대입 어림수 + 통과 여부(자바 약 10^8(1억) 연산/초 기준).

격자면 대개 O(칸수)=O(n*m). 재귀면 호출 수 x 호출당 비용.

## 7. 타입/오버플로 (Jesse에서 데임)

제약을 읽고, 값·합·곱의 최대가 int(약 21억, 정확히 2,147,483,647)를 넘으면 **long**. mod가 10^10 규모면 long.

## 8. 나의 반복 함정 (이것만 조심하면 절반은 산다)

- **스친 정답 승격**: 번뜩인 생각("차라리 정렬?", "caching?")에서 멈춰 "이게 답 아닌가?"를 따져라. 여러 번 스치고도 승격 못 한 이력 있음.
- **직전 모델 전이 금지**: 방금 푼 문제의 방식을 그대로 옮기지 말고, "이 문제의 이동/연결 규칙"을 지문에서 새로 읽어라.
- **최단 = dist를 파동으로 채우기**, 경로 수집이 아니다.
- **복잡도 먼저**: 브루트포스라도 짜기 전에 그 복잡도를 세서 통과 여부를 판단(못 세면 병목·최적화도 안 보임).
