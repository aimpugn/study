# 패턴 결정 가이드 — 접근이 안 잡히거나 도중에 흔들릴 때 방향 잡기

> "무엇으로 풀지"를 정하는 곳. 문법은 `cheatsheet`, 멘탈·막힘 대응은 `PLAYBOOK`.
> 1번 표로 도구를 고르고, 2번에서 그 도구가 어떻게 움직이는지 그림으로 확인한다.

## 1. 신호 -> 도구 (문제에서 이 말이 보이면 이걸 꺼낸다)

| 문제 신호 | 도구 | 핵심 자료구조 |
|---|---|---|
| 최단 거리/최소 횟수 + 가중치 없음 | BFS | 큐 + dist[][] |
| 연결 덩어리/영역/전부 방문/개수 | flood fill (BFS든 DFS든) | 큐 or 재귀 + visited |
| 가장 작은/큰 것을 반복해 꺼냄 | 힙 | PriorityQueue |
| 같은 부분문제를 다시 계산(겹침) | DP/메모 | dp[] |
| 정렬된 것에서 찾기/경계 조건 | 이분탐색 | lo/mid/hi |
| 연속 구간/창(window) | 슬라이딩 윈도우 | 두 포인터 |
| 최근 것부터/짝 맞추기 | 스택 | ArrayDeque |
| 모든 조합·순열 생성 | 백트래킹 | 재귀 + mark/unmark |

## 2. 패턴별 "어떻게 움직이나" (작은 예로 그림 잡기)

**BFS (최단, 파동처럼 퍼짐)** — (0,0)부터 각 칸의 최소 칸수를 dist에 파동으로:
```
0 1 2     시작 0에서 한 겹씩 +1로 바깥으로 퍼진다.
1 2 3     큐(FIFO)라 가까운 것부터 나와서, 목표에 "처음 닿은 순간 = 최단".
2 3 4     그래서 경로를 모을 필요 없이 dist만 채우면 답.
```

**flood fill (이어진 덩어리)** — 1로 이어진 칸을 다 세기. 찾은 칸이 다시 출발점이 됨:
```
1 1 0     (0,0)->이웃 (0,1),(1,1)->그 이웃 (1,2)... "이웃의 이웃의 이웃"으로 꺾어가며
0 1 1     이어진 1을 전부 방문(visited로 두 번 안 셈). 큐(BFS)든 재귀(DFS)든 같다.
          직선으로 긋는 게 아니라 연쇄로 퍼지는 게 핵심.
```

**힙 (최솟값/최댓값 반복 추출)** — 정렬 전체를 안 하고 매번 극값만:
```
넣기: 5, 1, 3   ->   꺼내면 1, 3, 5 (항상 최솟값이 꼭대기)
Jesse: 두 최솟값 꺼내 -> 섞어 -> 다시 넣기, 반복. 매번 최솟값만 O(log n)에.
```

**DP/메모 (겹치는 부분문제)** — 같은 걸 다시 안 계산하고 저장해 재사용:
```
Davis 계단 f(n)=f(n-1)+f(n-2)+f(n-3). 여러 경로가 f(3)을 또 계산 -> 지수 폭발.
dp[3]에 한 번 저장하고 꺼내 쓰면 선형: dp[0]=1; dp[i]=dp[i-1]+dp[i-2]+dp[i-3]
```

**이분탐색 (정렬된 것에서 반씩 버림)**:
```
[1,3,5,7,9]에서 7 찾기:  가운데 5 < 7 -> 오른쪽만 남김 -> 가운데 7 = 찾음.
매번 절반이라 O(log n). lo/hi로 "왼쪽 다 거짓 / 오른쪽 다 참"의 경계도 찾는다.
```

**슬라이딩 윈도우 (연속 구간, 두 포인터)**:
```
[2,1,5,1,3] 길이 3 최대합:  right로 값 더하고, 창이 3 넘으면 left 것을 뺀다.
전체를 매번 다시 더하지 않고 합을 들고 다녀서 O(n). (창을 밀며 더하기/빼기)
```

**스택 (최근 것부터 / 짝 맞추기)**:
```
괄호 "([)":  '(' push, '[' push, ')' 만나면 pop해 짝 확인 -> 짝은 '['이라 불일치.
열면 쌓고 닫으면 최근 것과 맞춘다. 끝에 스택이 비면 정상.
```

**백트래킹 (모든 경우 생성)** — 고르고 -> 재귀 -> 되돌리기:
```
[1,2,3] 조합:  1 고름 -> {1,2},{1,3} -> 1 빼고(되돌리기) 2 고름 -> {2,3}...
순열은 used[]로 "안 쓴 것 전부", 조합은 start 인덱스로 "지난 건 안 봄"(순서 고정).
```

## 3. 격자 3형제 — 헷갈리지 마라 (이번에 여기서 왔다갔다 함)

셋 다 격자지만 "이웃"과 "무엇을 세나"가 다르다. **지문의 '이동/연결 규칙'을 정확히 읽어 구별.**

| 유형 | 이웃 정의 | 무엇을 | 예 |
|---|---|---|---|
| flood(덩어리) | 인접 칸, 찾은 칸이 다시 출발점 | 이어진 칸 수 | Connected Cells, Number of Islands |
| 최단 BFS | 인접 칸, 파동으로 dist | 최소 거리/횟수 | 미로 최단 |
| 미끄러짐(룩) | 한 방향 직선 위 모든 칸(while) | 최소 이동 횟수 | Castle on the Grid |

**함정(실제로 겪음)**: 직전 문제의 이동 모델을 그대로 옮기지 마라. Castle의 `while 미끄러짐`을 Connected Cells에 쓰면 꺾인 연결(예: (0,0)->(0,1)->(1,2))을 놓친다.

## 4. BFS vs DFS — 어떻게 고르나 (이번 고민)

- **최단 거리/횟수가 필요하면 -> 반드시 BFS** (DFS는 아무 경로나 먼저 닿아 최단 보장 못 함).
- **그냥 다 방문/개수/존재만이면 -> 아무거나.** DFS 재귀가 짧고, 깊은 재귀가 걱정되는 아주 큰 입력이면 BFS 큐.
- 둘은 같은 칸을 방문 순서만 다르게 훑는다 — BFS는 겹으로, DFS는 한 줄기로 깊이.

## 5. visited / 가드 어디에 두나 — DFS와 BFS가 다르다 (Q: 0칸을 미리 걸러도 되나?)

**핵심: 가드의 "집"을 한 곳으로 정하면 안 흔들린다. 그 집이 DFS와 BFS가 다르다.**

- **DFS(재귀)**: 가드의 집은 `flood` 첫 줄(base case). 이웃을 그냥 `flood(nr,nc)`로 부르고, 안에서
  `경계 밖 || visited || 안 채워짐 -> return 0`으로 거른다. 즉 **부르기 전에 미리 안 걸러도 된다** —
  0칸이나 격자 밖 좌표도 flood에 들어갔다 첫 줄에서 걸러진다(호출은 싸니 괜찮다).
  미리 걸러도(`if (유효) flood(...)`) **틀린 건 아니다** — 다만 검사가 두 곳(부르기 전 + base case)에
  흩어질 뿐이라 "안 하는 게" 아니라 "한 곳에 모으는 게" 낫다. 재귀는 base case가 그 집.
- **BFS(큐)**: 가드의 집은 "큐에 넣기 전". 여기선 **미리 거르는 게 필수** —
  `if (유효 && 미방문) { visited=true; enqueue }`. 넣고 나서(꺼낼 때) 검사하면 같은 칸이 여러 이웃에게서
  큐에 여러 번 들어가 중복·무한이 된다. 그래서 넣기 전에 걸러 + 표시.
- **0/벽 칸은 visited 마크 자체가 불필요** — 조건 검사(isFilled/막힘)가 이미 막으니까. visited는 "채워진
  칸을 두 번 세지 않기"용.

정리: **DFS = base case에서 거른다(부르기 전 필터는 불필요, 해도 무해). BFS = 넣기 전에 거른다(필수).**

## 6. 몸통 골격 (외워두면 빈 화면에서 바로 시작)

격자 순회: `for (r=0..n) for (c=0..m) { ... }`

BFS (최단/파동):
```
dist 전부 -1; queue=[시작]; dist[시작]=0
while (큐 안 빔): cur=꺼냄
  for (dir): 이웃 계산; if (유효 && 미방문) { dist[이웃]=dist[cur]+1; visited/enqueue }
```
DFS flood (덩어리 크기):
```
int flood(r,c):
  if (경계 밖 || visited || 조건X) return 0     // <- 가드의 집
  visited[r][c]=true; size=1
  for (dir): size += flood(이웃)               // 이웃은 그냥 부름
  return size
```
백트래킹 (모든 경우): `mark; rec(...); unmark   // 되돌리기(unmark)가 핵심`

## 7. 복잡도 4박자 (약점 — 매번 이 순서로 소리 내어)

1. 변수 정의: n, m이 각각 뭔지.
2. 바깥 루프 횟수 x 반복당 비용.
3. 곱(중첩)/합(순차), 지배항만.
4. 제약 대입 어림수 + 통과 여부(자바 약 10^8(1억) 연산/초).

격자면 대개 O(칸수)=O(n*m). 재귀면 호출 수 x 호출당. BFS/flood도 각 칸 1번이라 O(n*m).

## 8. 타입/오버플로 (Jesse에서 데임)

제약을 읽고, 값·합·곱의 최대가 int(약 21억, 정확히 2,147,483,647)를 넘으면 **long**. mod가 10^10 규모면 long.

## 9. 나의 반복 함정 (이것만 조심하면 절반은 산다)

- **스친 정답 승격**: 번뜩인 생각("차라리 정렬?", "caching?")에서 멈춰 "이게 답 아닌가?"를 따져라. 여러 번 스치고도 승격 못 한 이력 있음.
- **직전 모델 전이 금지**: 방금 푼 문제의 방식을 그대로 옮기지 말고, "이 문제의 이동/연결 규칙"을 지문에서 새로 읽어라.
- **최단 = dist를 파동으로 채우기**, 경로 수집이 아니다.
- **복잡도 먼저**: 브루트포스라도 짜기 전에 그 복잡도를 세서 통과 여부를 판단(못 세면 병목·최적화도 안 보임).
