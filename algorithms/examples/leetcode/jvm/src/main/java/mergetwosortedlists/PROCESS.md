# Merge Two Sorted Lists (LeetCode 21) — 풀이 회고

> **이 문서를 쓰는 법.** 위에서부터 다 읽는 문서가 아닙니다. 먼저 바로 아래 30초 카드만 보고 코드를 머릿속으로 떠올려 보세요. 떠오르면 통과. 안 떠오르면 실패가 아니라 정상이고, 막힌 칸만 골라 아래 산문을 펼치면 됩니다. 두 리스트가 어떻게 한 줄로 합쳐지는지 안 그려지면 같은 폴더의 `PROCESS.html`에서 단계를 넘겨 보세요.

## 30초 카드

```
문제 신호 : "정렬된 두 연결 리스트를 하나의 정렬된 리스트로 합쳐라"
한 줄     : dummy 꼬리(curr)에 두 리스트의 앞 중 작은 쪽을 이어 붙이고, 그쪽만 한 칸 전진
키워드    : 1) dummy 머리로 첫 노드 특수처리를 없앤다   2) 두 앞을 비교, 같으면 list1(<=)   3) 한쪽이 비면 나머지를 통째로 잇는다
함정 단서 : 노드가 이미 있는데 new ListNode로 값을 복사하고 있지 않나? (복사 말고 그 노드를 splice하면 공간 O(1))
```

## 어디서 막혔나 — 실제 실수의 기록

이 절은 자기비난이 아니라 재발 방지 장치입니다. 정직하게 적으면, **이 세션엔 알고리즘 실수가 없었습니다 — 자력으로 정답(3/3 통과)에 도달했습니다.** dummy 머리에 커서를 두고 두 리스트를 훑어 작은 쪽부터 잇고 한쪽이 끝나면 남은 쪽을 쏟는 골격이 정확했고, `<=` 비교로 같은 값에서의 안정성까지 맞췄습니다. 그러니 여기 적을 것은 "실수"가 아니라 **미전이(전이되지 않은 개선)** 한 가지입니다.

직전에 푼 Reverse Linked List(206)에서 두 카드를 배웠습니다 — "리스트를 만들 땐 dummy 머리 + 커서 하나"와 "값을 복사하지 말고 기존 노드의 화살표를 다시 이어 공간을 O(1)로". 이번 풀이는 **앞 카드는 전이했지만 뒤 카드는 전이하지 못했습니다.** `curr.next = new ListNode(list1.val)`로 매 단계 새 노드를 찍어, 결과 길이만큼(n+m) 추가 공간을 썼습니다. 정답이지만 공간이 O(n+m)입니다. 노드는 이미 두 입력 안에 존재하니, 새로 만들지 말고 그 노드 자체를 이어 붙이면(splice) 공간이 O(1)로 떨어집니다. 막힌 게 아니라, 더 나은 길의 카드가 손에 안 잡힌 것입니다 — 다음 연결 리스트 문제(재배열 143, 머지 k 23)에서 같은 미전이가 반복되지 않도록 그 형태를 적어 둡니다.

작은 세션 디테일 하나 — 디버그 `System.out.println`과 인자 없는 `toArray()` 주석 한 줄이 풀이에 남아 있었습니다. 동작에는 영향이 없지만 제출 전 지우는 습관을 들이면 좋습니다.

## 핵심 사고 — 왜 이렇게 푸는가

카드가 떠오르지 않을 때 이 절만 읽고 같은 결론에 도달하도록, 사고 순서대로 적습니다.

**무엇이 상태인가.** 합쳐진 결과의 꼬리를 가리키는 손(`curr`)과, 두 입력 리스트의 현재 맨 앞입니다. 결과의 머리는 따로 들지 않습니다 — 가짜 머리 `dummy`를 하나 두면 진짜 머리는 늘 `dummy.next`로 고정되기 때문입니다. 이 `dummy`가 첫 노드 특수처리와 빈 입력 가드를 한꺼번에 없앱니다(둘 다 비면 `dummy.next`가 그대로 `null`).

**결정의 순간.** 두 리스트가 모두 살아 있는 동안, 매 단계 두 앞을 비교해 작은 쪽을 `curr.next`에 잇고 그 리스트만 한 칸 전진합니다. 같은 값이면 `list1`을 먼저(`<=`) 잇습니다 — 값으로는 어느 쪽을 먼저 넣든 정렬은 맞지만, `<=`로 고정해 두면 동작이 안정적이고 머릿속에서 헷갈릴 일이 없습니다.

**핵심 개선 — 복사가 아니라 splice.** 여기서 "잇는다"가 두 갈래입니다. 값을 복사해 새 노드를 만들어 붙이면(`curr.next = new ListNode(list1.val)`) 결과 길이만큼 새 노드가 생겨 공간이 O(n+m)입니다. 반면 고른 노드 자체를 붙이면(`curr.next = list1`) 새 노드가 0개라 공간이 O(1)입니다. 두 리스트의 노드는 이미 메모리에 다 있으니, 다시 만들 이유가 없습니다. 이게 206에서 값 복사(스택) 대신 포인터 재배선(in-place)으로 공간을 줄였던 것과 정확히 같은 수입니다.

**마무리.** 한쪽 리스트가 비면 남은 쪽은 이미 정렬된 채로 이어져 있으니, 노드를 하나씩 옮길 필요 없이 그 머리를 `curr.next`에 통째로 답니다(`curr.next = (list1 != null) ? list1 : list2`). 단, splice는 입력 노드의 `next`를 바꿔 원본 리스트를 소비합니다 — 호출자가 원본을 보존해야 한다면 그때는 복사 버전이 맞습니다.

## 손으로 따라가기 — `[1,2,4]`와 `[1,3,4]`

merge는 "두 앞을 비교해 작은 쪽을 떼어 붙인다"가 전부라, 화살표 그림보다 단계 표가 한눈에 들어옵니다. 매 단계 두 리스트의 맨 앞만 보면 됩니다(같으면 list1).

```
step | list1 앞  list2 앞 | 고른 것     | 결과
-----+-------------------+------------+------------------
1    |   1         1      | list1의 1   | 1
2    |   2         1      | list2의 1   | 1 1
3    |   2         3      | list1의 2   | 1 1 2
4    |   4         3      | list2의 3   | 1 1 2 3
5    |   4         4      | list1의 4   | 1 1 2 3 4
6    |   -         4      | list2의 4   | 1 1 2 3 4 4   (list1이 비어 list2의 나머지를 통째로)
끝 → return dummy.next = 1 1 2 3 4 4
```

step 2가 이 문제의 감각입니다 — `list1`의 앞(2)이 `list2`의 앞(1)보다 크니, 이번엔 `list1`을 건드리지 않고 `list2`만 전진시킵니다. 두 손이 따로 움직인다는 것, 그게 핵심입니다. step 6은 한쪽이 비는 순간으로, 복사 버전이라면 남은 노드를 하나씩 옮기지만 splice 버전은 남은 머리를 한 줄로 잇고 끝납니다.

## 뼈대 압축

```
dummy = new Node(); curr = dummy
while (list1 != null && list2 != null):
    if (list1.val <= list2.val):       # <= : 같으면 list1 먼저(안정성)
        curr.next = list1; list1 = list1.next     # 새 노드 X, 노드 자체를 splice
    else:
        curr.next = list2; list2 = list2.next
    curr = curr.next
curr.next = (list1 != null) ? list1 : list2       # 남은 쪽 통째로
return dummy.next

시간 O(n+m) -- 각 노드를 한 번씩 본다. 공간 O(1) -- 새 노드 없이 기존 노드를 다시 잇는다.
값 복사 버전도 시간은 같은 O(n+m)이지만 공간이 O(n+m).
```

## 패턴 전이 — 이 뼈대가 다시 나오는 곳

이 문제의 뼈대는 **"두 정렬 시퀀스의 앞만 비교해 작은 쪽을 떼어 붙인다"**입니다. 전체를 다시 정렬하지 않고 앞 둘만 본다는 것이 핵심이고, 이게 머지 정렬(merge sort)의 합치기 단계 그 자체입니다. Merge k Sorted Lists(LC 23)는 리스트가 k개라 "두 앞 비교"를 "k개의 앞 중 최소 고르기"로 키워 힙으로 앞을 관리하거나, 둘씩 짝지어 이 머지를 반복합니다. Reorder List(LC 143)는 뒤 절반을 뒤집은 뒤 두 리스트를 번갈아 끼우는 변형이고, Merge Sorted Array(LC 88)는 같은 비교-선택을 배열에서, 덮어쓰기를 피하려 뒤에서부터 채웁니다.

한 층 내려가면 공통 원리는 **"이미 정렬된 것끼리 합칠 땐 앞만 본다"**입니다. 각 시퀀스가 정렬돼 있다는 불변식 덕에 전역 비교가 필요 없어진다는 것 — 이 한 문장이 투포인터 병합 전반을 관통합니다.

## 코드에서 배운 것

복사와 splice의 차이는 차수가 아니라 공간입니다. 둘 다 노드를 한 번씩 보는 O(n+m) 시간이지만, 복사는 결과만큼 새 노드를 만들어 O(n+m)을 쓰고 splice는 기존 노드의 `next`만 다시 이어 O(1)입니다. 206의 스택 우회 대 in-place와 똑같은 대비라, "노드가 이미 있으면 새로 만들지 말라"는 한 문장으로 두 문제가 묶입니다.

`<=`와 `<`의 차이는 결과 값으로는 안 드러나지만 안정성에서 갈립니다. 같은 값에서 `<=`는 `list1`을 먼저 이어, 원래 순서를 보존하는 안정 병합이 됩니다.

`dummy`(가짜 머리) 노드 하나가 머리/커서 혼동과 빈 입력 가드를 동시에 없앱니다. 진짜 머리가 늘 `dummy.next`라, 첫 노드만 따로 만들 필요가 없습니다.

## 복습 계획 (R1~R4)

이 문제는 자력으로 풀었으니, 복습의 초점은 "정답 복원"이 아니라 **splice 카드를 손에 붙이는 것**입니다. 다음 연결 리스트 문제에서 값 복사로 되돌아가지 않는 게 목표입니다.

- **R1 (2026-06-26, 완료):** 값 복사로 자력 정답. splice 미전이를 기록하고, splice 베스트 + 단계 표 트레이스 + 시각화를 자산화.
- **R2 (2~3일 뒤):** 빈 파일(`Solution260629.java` 등)에서 splice 버전으로 재구현. 코드 암기가 아니라 "노드가 이미 있다 -> 복사 말고 그 노드를 잇자"는 씨앗에서 출발하는지 본다.
- **R3 (1주 뒤):** 코드 없이 말로 설명 — "왜 dummy를 쓰나, 왜 `<=`인가, splice가 왜 공간 O(1)인가" 세 질문에 답한다.
- **R4 (2~3주 뒤):** 카드만 보고 제한 시간 재풀이. Merge k Sorted Lists(23)나 Reorder List(143)로 전이를 확인한다.
