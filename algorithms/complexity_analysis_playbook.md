# 복잡도 분석·발화 플레이북 (라이브 코딩용)

라이브 면접에서 "시간/공간 복잡도가 어떻게 되나요?"에 막히지 않고 **소리 내어 유도**하기 위한 문서입니다. 루프는 익숙하니 가볍게 짚고, 애매한 재귀·DP·상각(amortized)에 무게를 둡니다. 면접관은 정답 숫자만큼이나 "어떻게 그 숫자에 도달했는지"를 봅니다.

## 0. 모든 분석의 첫 문장: "n을 무엇으로 둘까"

복잡도를 말하기 전에 **변수부터 정의**합니다. 이게 빠지면 같은 O(n²)도 무슨 n인지 흐려집니다.

> 발화 템플릿: "입력 크기를 정의하면, 배열 길이를 n, (있다면) 값의 최댓값을 V, 문자 집합 크기를 σ라 하겠습니다."

격자 문제면 행 m, 열 n. 문자열이면 길이 L과 문자종류 σ. 그래프면 정점 V, 간선 E. **변수를 먼저 못 박아야** 그다음 모든 문장이 명확해집니다(예: "정렬은 O(n log n)"인지 "O(L log L)"인지가 변수 정의로 갈립니다).

## 1. 루프 (익숙한 영역 — 규칙만)

- **중첩은 곱, 순차는 합, 지배항만 남긴다.** `for i: for j:` → O(n²). `for(정렬) ; for(스캔)` → O(n log n + n) = O(n log n).
- 안쪽 루프가 입력이 아니라 **제약에 묶이면** 그 제약이 변수다. 예: 문자열에서 같은 문자를 다시 스캔해도 문자 집합이 σ로 제한되면 O(n·σ)이지 O(n²)가 아니다.
- 흔한 실수: worst case를 "전부 다른 경우"로 착각. 제약(σ, 값 범위)을 분석에 넣는다.

> 발화: "바깥 루프가 n번, 각 반복에서 O(log n) 작업이라 곱해서 O(n log n)입니다."

## 2. 상각(amortized) — "겹쳐 보이지만 사실 선형"

라이브에서 가장 자주 틀리는 지점입니다. **두 포인터·슬라이딩 윈도우·단조 스택**은 코드에 루프가 둘처럼 보여도 각 원소가 자료구조에 **딱 한 번 들어가고 한 번 나오므로** 전체가 O(n)입니다.

- 슬라이딩 윈도우: `right`가 n번 전진, `left`도 **합쳐서** 최대 n번 전진. 둘을 더해도 2n → O(n). (곱이 아니라 합이다.)
- 단조 스택(예: Daily Temperatures): 각 원소 push 1회 + pop 최대 1회 → 전체 push/pop이 2n → O(n).

> 발화: "안에 while이 또 있어 O(n²)처럼 보이지만, left 포인터는 전체에서 최대 n번만 움직입니다. 각 원소가 창에 한 번 들어가고 한 번 나가므로 상각하면 O(n)입니다."

이 "각 원소를 상수 번 만진다"는 문장이 상각의 핵심 발화입니다.

## 3. 재귀 — 점화식과 재귀 트리로 푼다

재귀는 "한 호출이 자기보다 작은 호출 몇 개를 부르고, 호출당 얼마를 쓰는가"를 **점화식 T(n)**으로 쓰면 풀립니다. 또는 **재귀 트리**(노드 = 한 호출, 노드 비용 = 그 호출의 자기 작업)를 그려 전체 노드 비용을 합칩니다.

세 가지 대표 패턴만 알면 대부분 커버됩니다.

**(a) 단일 재귀 — 보통 선형.** 한 번 호출이 한 번(또는 상수 번) 호출. 예: 연결 리스트/단순 트리 DFS. 각 노드를 한 번 방문 → 노드 수에 비례.
- 트리 DFS: `T(n) = T(left) + T(right) + O(1)`, 노드 n개를 각 한 번 → **O(n)**. 공간은 콜스택 = 트리 높이 h → 균형이면 O(log n), 치우치면 O(n).
- 격자 DFS(섬 세기): 칸 m·n개를 visited로 한 번씩 → **O(m·n)**.

**(b) 분할 정복 — 절반씩 나누면 O(n log n) 근처.** `T(n) = 2·T(n/2) + O(n)` → **O(n log n)**(병합 정렬). 직관: 트리 깊이 log n층 × 각 층 O(n) 작업. `T(n)=2T(n/2)+O(1)`이면 O(n)(노드 합이 지배). 마스터 정리를 외우기보다 "층수 × 층당 비용"으로 재귀 트리를 그려 합치면 됩니다.
- 이분 탐색: `T(n)=T(n/2)+O(1)` → 층수 log n, 층당 O(1) → **O(log n)**.

**(c) 이중 재귀(메모 없음) — 지수, 메모하면 다항.** 각 호출이 자신을 2번 이상 부르고 겹치는 부분문제를 다시 계산. 예: 순진한 피보나치 `fib(n)=fib(n-1)+fib(n-2)` → 재귀 트리 노드가 약 2ⁿ개 → **O(2ⁿ)**. 같은 부분문제가 반복되므로 **메모이제이션을 붙이면 각 상태를 한 번만 계산** → O(n)으로 떨어집니다. 이 "지수 → 메모 → 다항" 전이가 DP의 입구입니다.

> 발화(트리 DFS): "각 노드를 정확히 한 번 방문하니 시간은 노드 수 O(n)이고, 공간은 재귀 콜스택이라 트리 높이만큼 — 균형 트리면 O(log n), 한쪽으로 치우치면 최악 O(n)입니다."
>
> 발화(순진한 재귀): "이대로면 같은 부분문제를 반복 계산해 O(2ⁿ)입니다. 메모이제이션으로 각 부분문제를 한 번만 풀면 O(n)으로 줄일 수 있습니다." ← 면접에서 큰 가점.

## 4. DP — 시간 = 상태 수 × 전이 비용, 공간 = 테이블 크기

DP 복잡도는 공식 하나로 거의 끝납니다.

```
시간 = (상태의 개수) × (한 상태를 채우는 데 드는 전이 비용)
공간 = (테이블 크기)   [+ top-down이면 재귀 콜스택]
```

- **상태 수**: dp 배열의 칸 수. 1차원 `dp[i]`면 O(n), 2차원 `dp[i][j]`면 O(n·m).
- **전이 비용**: 한 칸을 채울 때 보는 이전 상태의 수. `dp[i]=dp[i-1]+dp[i-2]`면 O(1), `dp[i]=max(dp[j] for j<i)`면 O(n).

예시로 굳히기:
- 1차원·상수 전이 (House Robber, 피보나치): 상태 n × 전이 O(1) = **O(n)** 시간, O(n) 공간(→ 직전 2개만 들면 **O(1)** 공간).
- 2차원·상수 전이 (Unique Paths, Edit Distance): 상태 n·m × O(1) = **O(n·m)** 시간/공간(→ 한 행만 굴리면 O(min(n,m)) 공간).
- 1차원·선형 전이 (LIS 기본형): 상태 n × 전이 O(n) = **O(n²)**.

> 발화(2D DP): "상태는 dp[i][j]로 n·m개이고, 각 칸을 위/왼쪽 두 칸에서 O(1)로 채웁니다. 따라서 시간 O(n·m), 공간도 테이블이라 O(n·m)인데, 한 행만 유지하면 O(m)으로 줄일 수 있습니다."

top-down(메모 재귀)이면 시간은 같고 **공간에 재귀 콜스택을 더합니다**: "공간은 메모 테이블 O(n·m) + 콜스택 O(n+m)입니다."

## 5. 공간 복잡도 — 자주 빠뜨리는 셋

시간만 말하고 공간을 잊는 경우가 많습니다. 공간은 **세 군데**를 봅니다.

1. **보조 자료구조**: 해시맵·visited 배열·스택·큐 → 담는 원소 수.
2. **재귀 콜스택**: 재귀 깊이 × 프레임. 트리 높이, 격자라면 최악 칸 수(섬 세기 300×300이면 깊이 9만 → StackOverflow 위험, BFS면 회피).
3. **출력**: 결과로 만드는 배열/리스트 크기(보통 입력에 비례. "출력 제외하면 O(1)"이라 말하면 더 정확).

in-place로 바꾸면 보조 공간을 O(1)로 줄일 수 있는지도 한마디 하면 좋습니다(예: 섬 세기에서 visited 대신 grid를 직접 '0'으로 덮기).

> 발화: "보조 공간은 해시맵에 최대 n개라 O(n), 재귀 콜스택은 깊이 O(log n), 출력은 별도로 O(k)입니다."

## 6. 발화 4박자 (외워서 그대로 말하기)

복잡도 질문에 답할 때 이 순서로 말하면 빠짐이 없습니다.

```
1) 변수 정의   "n을 배열 길이라 하면,"
2) 시간 유도   "바깥 루프 n번 × 안쪽 O(log n) = O(n log n)입니다."
3) 공간 유도   "보조 자료구조 O(n) + 콜스택 O(log n), 출력 제외하면 O(n)입니다."
4) 개선 여지   "정렬이 병목이라 더 줄이긴 어렵지만, 해시로 정렬을 피하면 평균 O(n)도 가능합니다."
```

4번(개선 여지)까지 닫으면 "최적화를 의식한다"는 신호라 가점입니다. 모르면 "이게 현재 제 최선이고, 병목은 여기입니다"까지만 해도 충분합니다.

## 7. 빠른 룩업 (패턴 → 복잡도)

| 패턴 | 시간 | 공간 | 한마디 |
|---|---|---|---|
| 단순 1중 루프 / 해시 1패스 | O(n) | O(n) | 각 원소 1회 |
| 정렬 후 스캔 | O(n log n) | O(n) 또는 O(1) | 정렬이 지배 |
| 두 포인터 / 슬라이딩 윈도우 / 단조 스택 | O(n) | O(1)~O(n) | 상각 — 각 원소 1회 들고 남 |
| 이분 탐색 | O(log n) | O(1) | 절반씩 |
| 트리/격자 DFS·BFS | O(노드+간선), 격자 O(m·n) | 콜스택/큐 = 높이 또는 너비 | 각 노드 1회 방문 |
| 분할 정복(병합 정렬류) | O(n log n) | O(n) | 층수 log n × 층당 n |
| 순진한 이중 재귀 | O(2ⁿ) | O(n) 콜스택 | 메모 붙이면 다항 |
| DP | 상태 수 × 전이 | 테이블(+콜스택) | 차원 축소 가능한지 보기 |
| 백트래킹(순열/부분집합) | O(n!) / O(2ⁿ) | O(n) 깊이 | 가지치기로 평균 단축 |

---

핵심 한 줄: **변수를 먼저 정의하고(1) → 시간은 "무엇을 몇 번 만지나"로(상각이면 합, 재귀면 트리, DP면 상태×전이) → 공간은 보조+콜스택+출력 셋을 보고 → 개선 여지로 닫는다.**
